# CyberPGM 仕様書 v0.1

作成: 2026-10-20（Claude）／実装: agy／承認: ユーザー

サイバーパンクRED を遊ぶ **人間GM向け** のセッション支援 Web アプリ。ルール・装備のデータベースを持ち、「戦闘」「商店」「シナリオ」の 3 画面でセッション進行を助ける。

---

## 1. 前提と方針（2026-10-20 ユーザー決定）

| 項目 | 決定 |
|---|---|
| 対象ルール | **サイバーパンクRED**（日本語版：ホビージャパン）。2020 は対象外 |
| GM | 人間。AI による会話生成・シナリオ自動生成・裁定は **実装しない** |
| ダイス | リアルダイス。出目を入力し、アプリが修正値・DV と比べて成否やダメージを計算する。例外としてイニシアチブはアプリが自動でロールする（§5.1） |
| 端末 | PC とスマートフォン（ブラウザ。レスポンシブ／PWA） |
| 公開範囲 | **対面セッションで、GM の PC がつながっている Wi-Fi 内のみ**。自宅でも出先でもよく、将来は Windows のノートパソコンをホストにする（2026-10-21 ユーザー決定。それまでは「自宅 Wi-Fi 内のみ」）。常設サーバー・レンタルサーバーは持たない。プレイヤーに Tailscale は使わせない。インターネットには公開しない（2026-10-20 ユーザー決定） |
| 画面 | **戦闘・商店・シナリオ** の 3 タブ（+ 管理用のデータベース画面） |
| 実装担当 | **コードは agy が書く**。Claude は調査・仕様・agy への指示書・レビューを担当 |

## 4. システム構成

```
[プレイヤーのスマホ] --(GM の PC と同じ Wi-Fi)--> [GM の PC: CyberPGM（セッション中だけ起動）]
                                               ├─ Web API + 静的配信
                                               ├─ SQLite (data/cyberpgm.db)
                                               └─ data/images/ (本のスキャン等, git 管理外)
```

| 層 | 採用（推奨） | 理由 |
|---|---|---|
| 言語 | TypeScript（フロントエンドとバックエンドで共通） | 型を共有でき、agy が扱いやすい |
| フロントエンド | React + Vite、PWA | スマホでも動く。ホーム画面に追加できる |
| リアルタイム同期 | WebSocket（または SSE） | 戦闘の状態（イニシアチブや HP）を GM 端末とプレイヤー端末で同期する |
| バックエンド | Node.js + Hono（または Fastify） | 軽量 |
| DB | SQLite + Drizzle ORM | 1 ファイルなのでバックアップが簡単 |
| 実行 | **GM の PC でセッションのときだけ起動する**（`npm start` かランチャー。Linux と Windows の両方で動かす）。常駐させない。待ち受けは LAN の IP のみ。終了すれば外部からは何も見えない | 常設サーバーを持たない（2026-10-20 ユーザー決定） |
| 認証 | **なし**（2026-10-20 ユーザー決定: ログインやパスワードは要らない）。GM 画面は URL を開けばそのまま使える。プレイヤーは QR（セッションコード入り URL）から参加してキャラを選ぶだけ | ユーザーが求めていない機能は作らない |
| 参加方法 | 起動すると GM の画面に **QR コード**（`http://<GM の PC の LAN IP>:<port>/player?join=<セッションコード>`）を出す。プレイヤーはスマホで読み取り、自分のキャラを選ぶ。QR の IP は GM が開いたアドレスではなく、サーバーが待ち受けている LAN の IP にする。IP が複数あるときは Wi-Fi を優先し、仮想アダプタ（WSL・VirtualBox など）は後回しにする（Phase 5h） | アプリのインストールやアカウントは不要 |

## 5. 画面仕様

### 5.0 ウィンドウ構成（2026-10-20 ユーザー決定）

GM 用とプレイヤー用でウィンドウ（URL）を分ける。

| ウィンドウ | URL（案） | 使う人・端末 | 内容 |
|---|---|---|---|
| **GM ウィンドウ** | `/gm` | GM の PC | タブ: 戦闘 / シナリオ / 商店 / PC / 技能 / DB ＋「保存・読み込み」。全情報と全操作 |
| **戦闘（別ウィンドウ）** | `/gm/combat` | GM の PC（2 枚目のモニターなど） | GM ウィンドウの戦闘タブと同じ状態を、コンパクトな配置で表示する。「別ウィンドウで開く」で開き、両方が同期する |
| **共有画面** | `/screen` | 卓の TV・モニター | GM が「プレイヤー画面に出す」とした背景・コマ・行動順・味方の HP。操作はできない |
| **プレイヤー: キャラシート** | `/player` | 各プレイヤーのスマホ | **自分のキャラシートだけ**（能力値・技能の基本値・HP/SP・武器・防具・サイバーウェア・所持品・所持金）。プレイヤーは一箇所に集まるので、盤面や他人の情報はスマホに出さない（2026-10-20 ユーザー決定） |
| **プレイヤー: 行動** | `/player/act` | 各プレイヤーのスマホ | 行動の選択肢を出す。**戦闘時**: 移動・遮蔽・射撃・照準射撃・身を隠す・リロードなど（自分の手番だけ選べる）。**ストーリー時**: GM が公開した「この場面の選択肢」＋一般的な行動（調べる・話す・交渉・脅す・隠れる）＋自由記述。選ぶと GM に届き、GM が DV を決めると「1d10・〇以上で成功」と内訳と出目パッドが出る。出目を入れて送信する。成功値を見せるかは GM の設定 |
| **プレイヤー: 装備・技能・商店**（2026-10-21 ユーザー決定） | `/player` の下のタブ（シート / 装備 / 技能 / 商店 / 行動 / 資料） | 各プレイヤーのスマホ | **装備**: 武器・防具・サイバーウェア・持ち物。タップで性能。**技能**: 基本値の一覧。**商店**: GM が「スマホに出す」にした店の在庫だけを見て、買いたい物を **GM に申請** する（申請だけではお金も持ち物も変わらない。GM が商店タブで承認すると購入になる）。品目は性能だけ見せ、効果・フレーバーは GM だけ。**行動**には「使える技能」（戦闘で使う・探索で使う）を出し、押すと計算式と難易度ごとの成功率を出す |
| **プレイヤー: キャラ作成** | `/player/create` ほか（§12） | 各プレイヤーのスマホ | 事前のキャラ作成。画像・能力値・**技能の選択**・装備の購入（GM が決めた開始資金の範囲で。シナリオごとに決められる §5.8。サイバーウェアは人間性も表示）→ GM に送る |

- **シナリオ（作成・進行）は GM ウィンドウにだけ置く**。プレイヤーには、GM が出した背景・ハンドアウト・手がかりだけが届く
- 戦闘の行動ボタン（ターン進行ガイド）は GM ウィンドウにだけ置く。プレイヤーはスマホの行動画面から選ぶか、口頭で GM に伝える
- 同期は WebSocket で行う。GM ウィンドウの操作が状態の正本になる。プレイヤーが送った出目は GM のターン進行ガイドに入る
- GM ウィンドウの上部タブ（**戦闘 / シナリオ / 商店 / PC / 技能 / DB**）と「保存・読み込み」、全文検索。スマホでは下部タブにする

### 5.0.1 判定の表示と結果の自動反映（2026-10-20 ユーザー決定。戦闘・ストーリー共通）

- **用語**: 画面では「DV」を使わず **「難易度」** と表記する（例: 「14 vs 難易度 15 → 2 以上で成功」）。難易度の目安の一覧は **「難易度目安（DV値）」** と表記する（2026-10-20 ユーザー決定）。コード・DB の名前は `dv` のままでよい。この仕様書の「DV」は難易度のこと

- **判定のあるボタンには、押す前から計算式と成功ラインを出す**。GM 側（行動ボタン、手順のダイス行、判定ボード）とプレイヤー側（行動ボタン）の両方。攻撃・防御・ストーリーの判定すべてが対象
  - 例: 「射撃 — REF 8 + 拳銃 6 = 14 vs DV 15 → 2 以上で成功」「回避 — DEX 6 + 回避 6 = 12 vs 攻撃 18 → 6 以上で回避」「説得 — COOL 6 + 説得 2 = 8 vs DV 13 → 6 以上で成功」
  - 成功ライン = `DV − 基本値 + 1`（DV を超える必要があるため）。防御側の対抗判定は `相手の合計 − 基本値`（同値は防御側の勝ち）。11 以上なら「10 → 追加ロールで ○ 以上」と出す。ルールの根拠は docs/RULES_CHECK.md
  - 対抗判定で相手がまだ振っていないときは「相手の合計を超えれば成功」と出し、相手の出目が入った時点で数値に更新する
  - 重傷・瀕死のペナルティ、照準、状況修正なども式に含めて表示する- **ダイスの依頼機能は作らない**（2026-10-20 ユーザー判断: 「振って」は GM が口で言う）。プレイヤーは自分のスマホの行動画面から出目を送る。防御（回避）も行動画面の「回避（GM に言われたとき）」から送る。GM 側には「○○ のスマホから入力 / 入力待ち」とだけ表示し、GM が代わりに入力してもよい
- **結果の自動反映**: 出目（スマホから届いたもの、または GM の入力）がそろうと、ルールエンジンが結果を計算し、手順の下に **「反映する内容」** を一覧で出す（例: 「ガンガー #2 HP 25 → 11」「状態 重傷（−2）になる」「SP 胴 7 → 6」「致命傷: 胴の表の結果」「ヴァイパー 弾 6/8 → 5/8」）。GM が **「確定して反映」** を押すと、以下が一度に書き換わる。「取り消す」で反映前に戻せる
  - HP、SP（頭/胴。貫通時の −1）、弾数
  - 状態: 重傷（−2）、瀕死（−4、死亡セーブ開始）、死亡、遮蔽中、隠れている、武器を落とした など。HP の変化から重傷・瀕死は自動で判定する
  - 致命傷（部位の負傷）: クリティカル時は致命傷表の出目を入れると、その結果を状態として付ける。照準射撃の部位効果（頭のダメージ 2 倍、持っている装備を落とす、脚の致命傷）も同じく反映する。効果の数値は表のデータどおりで、ルールの根拠は docs/RULES_CHECK.md
  - 盤面: コマの下の HP バー（味方色/敵色 → 黄=重傷 → 赤=瀕死）、致命傷や落とし物の印、落とした装備は足元のマスに置く（拾うにはアクション）、死亡・離脱したコマはグレーにする
  - 行動順バー: 名前の横に重傷・瀕死の印。死亡・離脱した参加者は手番を飛ばす
  - 反映先: GM の戦闘カード・盤面・行動順バー、戦闘の別ウィンドウ、TV 画面（敵は負傷状態だけ）、該当プレイヤーのスマホ。すべて同じ確定結果から書き換えるので、表示がずれない
- **プレイヤーのスマホ**: 確定した結果がすぐ届く
  - 行動画面の上に「GM が確定した結果」（例: 「射撃 1 発目: 命中 · ガンガー #2 に 14 ダメージ → 重傷」「あなたの弾 6/8 → 5/8」）
  - 自分が攻撃を受けたときは、キャラシートの上に赤い通知（「ガンガー #2 の射撃が命中 — 胴に 18 − SP 10 = 8 + クリティカル 5 → HP −13」）
  - キャラシートの HP・SP・弾数・状態・致命傷（効果の説明つき）が自動で更新される。重傷などのペナルティは、技能の基本値と行動画面の計算式・成功ラインに自動で入る
  - キャラシートの下に自分に関係するログ（ラウンドごとの被弾・攻撃・回復）
- **ストーリーの判定**も同じ流れにする。シナリオの選択肢に設定した結果（手がかりの公開、HP の増減、状態、アイテムの入手、警戒度など）を、GM の確定で自動で入れて本人のスマホにも出す


### 5.1 戦闘

リアルダイスの出目を入力し、判定・ダメージ・状態変化を計算・記録する。

**戦闘の準備**
- 参加者を追加する: PC、DB の NPC・モブ、シナリオのエンカウンターから一括投入
- 参加者ごとの値: 能力値（REF/DEX/BODY/WILL ほか）、技能、HP（現在/最大）、SP（頭/胴、現在/最大）、装備武器（残弾）、状態異常、致命傷

**画面レイアウト（敵味方パラメータ一覧）**（2026-10-20 ユーザー決定）
- PC では左に **味方**、右に **敵** の 2 列。上部に行動順バーを置く。スマホでは行動順バーの下で「味方／敵」をタブで切り替える
- 参加者ごとのカードに常に出すもの: 名前、HP バー（現在/最大、重傷・瀕死の色分け）、SP（頭/胴）、REF/DEX/BODY/MOVE、主要技能、装備武器（ダメージ・ROF・残弾）、状態異常、致命傷
- カードをタップすると詳細（全能力値・全技能・所持品・サイバーウェア）を開く
- 手番中の参加者のカードを強調表示し、攻撃の対象はカードをタップして選ぶ
- GM ビューでは敵の全パラメータを表示する。プレイヤービューで敵の数値をどこまで見せるかは GM が設定する（既定は名前と負傷状態だけ）

**行動順（自動）**（2026-10-20 ユーザー決定）
- 戦闘を開始すると、アプリが全員のイニシアチブ（REF + 1d10）を **自動でロールして並べる**。イニシアチブはリアルダイス方針の例外とする
- 設定で「PC だけ出目を手入力」に切り替えられる。入力された PC はその値で並べ替え、敵は自動ロールのまま
- 同値は REF の高い方を先にし、それも同じなら再ロールする。GM はドラッグで手直しできる
- 手番は自動で進行する（行動を確定すると次の参加者へ移る）。死亡・離脱した参加者は飛ばし、全員が終わったらラウンド数を増やす。途中参加の参加者は自動ロールして順番に差し込む

**戦闘開始: 参加者チェックと行動順の確定**（2026-10-20 ユーザー決定）
- 戦闘を始めると、まず **参加者チェック画面** を出す。PC 全員とエンカウンターの NPC を、サムネイル・名前・状態・HP つきで並べ、チェックで参加・不参加を切り替える。DB からの NPC 追加、モブの人数指定、味方 NPC の追加もここで行う
- 右側に行動順（REF + 1d10）を出す。NPC は自動ロール、PC は「スマホかこの画面で出目を入力」（設定で全員自動にもできる）。入力待ちの人を表示する
- 同値の扱い、振り直し、ドラッグでの手直しをしてから **「行動順を確定して戦闘開始」** で戦闘画面に移る

**サムネイル**（2026-10-20 ユーザー決定）
- 戦闘画面では、PC・NPC の **名前の左にキャラ画像のサムネイル** を置く（参加者カード、行動順、別ウィンドウ、参加者チェック）。画像がなければ頭文字を味方色・敵色で表示する

**ターン進行ガイド（GM ウィンドウのみ）**（2026-10-20 ユーザー決定）
- 手番が来ると「**〇〇のターンです**」と大きく表示し、そのキャラが今できる行動を **ボタン** で並べる
  - 移動アクション: 移動（MOVE に応じた距離を盤面で表示）、遮蔽に入る
  - アクション: 射撃、照準射撃、オートファイア、制圧射撃、近接攻撃、格闘、リロード、**身を隠す**、走る、技能を使う、アイテム・サイバーウェア、応急手当、その他（GM 裁定）
  - 武器や状態で使えない行動はグレー表示にし、理由を出す（例: オートファイア非対応の武器）
  - 移動アクションとアクションの使用状況を表示する
- ボタンを押すと、まず **その行動の説明文**（何をする行動か・何が必要か・何が起きるか。2〜3 文。アプリ側で自分の言葉で書き、ルールブックの文章は写さない）を出す。移動アクション（移動・遮蔽に入る）も同じ（2026-10-20 ユーザー決定）
- 続けて、その行動の **ルールブックに沿った手順** を順番に案内する。手順の中で「〇〇は 1d10 を振ってください（REF 8 + 拳銃 6 を加算）」のように、誰が何のダイスを振るかを示す
  - 出目は「出目を入力」（リアルダイス、既定）または「アプリで振る」で入れる
  - 対象や場所は、敵カードか盤面のコマ・マスをクリックして選ぶ。距離は盤面から自動で測る
  - **移動**: 「移動」を押すと、盤面に移動できるマス（MOVE の値のマス数。1 マス 2m）を青く表示する。移動先のマスをクリックするか、コマをドラッグして指定し、「移動を確定」で反映する。壁は通れず、他のコマのマスには止まれない。斜め移動の数え方は日本語版で確認して設定にする
  - **射線**: 射撃・照準射撃では、撃つ側から対象へ線を引く。緑=通る / 黄=遮蔽物越し（先に遮蔽物に当たる。遮蔽物の HP を表示）/ 赤=壁に遮られて撃てない。対象の選択欄にも「射線○ / 遮蔽越し / 射線×」を出す。GM は判定を上書きできる
  - **成功率に影響する要素**（アプリが自動で計算に入れる。数値と細部は日本語版で確認して `rule_constants` に置く）: 距離帯ごとの DV（武器種別）、照準の修正、オートファイアの DV 表、遮蔽物（対象ではなく遮蔽物に当たる）、対象の REF が高い場合の回避ロール、重傷・瀕死のペナルティ、状況修正（暗闇・煙など。GM が選ぶ）
  - 対象を取る行動（射撃・照準射撃・オートファイア・近接・格闘）は、手順の上に **対象の選択欄**（敵の名前ボタン＋距離）を出す
  - **照準射撃** はさらに **狙う部位**（頭部 / 手に持っている武器・装備 / 脚）を選ぶ。「武器・装備」を選んだら、**対象の所持品（DB の装備中アイテム）の一覧** から狙う物を選ぶ。結果の適用で、その装備を対象の手から外す（落とす）
  - 最後に計算の内訳と結果を表示し、「結果を適用」で HP・SP・弾数・状態を更新する
- 敵の手番も同じ画面で GM が操作する
- 行動の一覧と各手順は、コードに直接書かず、DB の `rule_constants`（`combat_actions`）に置く。**中身は日本語版ルールブックで確認してから確定する**（モックの手順は仮）

**攻撃判定**（入力: 攻撃者、武器、対象、距離 or 回避の選択、出目）
- 遠隔: `能力値 + 技能 + 修正 + 1d10` を、距離帯ごとの DV（武器種別の DV 表）、または防御側の回避ロールと比べる
- 近接: 攻撃側のロールと防御側の回避ロールを比べる（同値は防御側の勝ち）
- 1d10 で 10 が出たら追加で 1d10 を加算し、1 が出たら追加の 1d10 を減算する（追加の出目も入力させる）
- オプション: 照準（頭部 −8）、オートファイア、制圧射撃、無音・隠匿状態などの修正
- 修正値は内訳を表示する（例: REF 7 + 技能 6 + 照準 −8 + 出目 9 = 14 vs DV 13 → 命中）

**ダメージ**（入力: ダメージダイスの各出目）
- 合計から部位の SP を引いた値を HP から減らす。SP を貫通したら SP を 1 減らす（アブレーション）
- 頭部命中は SP を引いた後のダメージを 2 倍にする
- 出目に 6 が 2 個以上あればクリティカル: ボーナスダメージを加え、致命傷表へ誘導する（致命傷の出目を入力すると表から結果を引き、参加者に付与する）
- 重傷（HP が最大の半分未満）や瀕死の状態は自動判定し、ペナルティを表示する。死亡セーヴは入力補助のみ

**その他**
- 残弾の管理（射撃で減らし、リロードは 1 アクション）
- 状態異常・効果時間の管理（ラウンド経過で減らす）
- 戦闘ログ（判定の内訳つき）。終了時にシナリオのセッションログへ保存する
- **一手戻る**: 直前の行動の反映、または手番送りを戻す（HP・弾数・位置・手番・ラウンド）。何度でも戻れる
- プレイヤーのスマホでは、自分の HP・SP・弾数・手番を確認できる（行動の操作は GM が行う）。敵の表示範囲は上記の GM 設定に従う
- スマホの行動画面では、**攻撃する相手** と **使う武器**（持ち物の武器）を選んでから攻撃のボタンを押す。GM の戦闘画面に相手と武器が入る（2026-10-21 ユーザー指摘）
  - 攻撃のボタンの基準値は、選んだ武器の技能で出す（例: REF 8 + 拳銃 6 = 14）。照準射撃は −8、オートファイアはオートファイア技能でオートファイアできる武器だけ、近接攻撃は近接武器の技能（なければ素手で格闘）
- 文字だけで書いた武器（デモの PC など）は、品目が見つかれば戦闘の開始時とサーバー起動時に持ち物へ移し、戦闘で選べるようにする

**プレイヤー画面の見た目**（2026-10-21 ユーザー要望）: スマホの画面（参加・シート・行動・キャラ作成）は、サイバーパンクの端末風にする。ネオンの黄・シアン・マゼンタ、角を斜めに落としたパネル、走査線と格子の背景、上の帯に接続状態とハンドルネーム。GM の画面は今のまま

**手番と行動回数**（2026-10-21 ユーザー指摘で洗い出し）
- 1 ターンは **移動アクション 1 回＋アクション 1 回**。両方使うと **自動で次の手番へ** 進む（行動した人が倒れたときも進む）。アクションだけ使って動かないときは「手番を終える」
- 使い切った移動アクション・アクションは使えない。もう一度動くなら「走る」（アクションを使う）
- **2 回行動**:
  - ROF 2 の武器（拳銃・近接武器など）で 1 アクションに 2 回攻撃: 戦闘画面の「第2攻撃を行う」
  - 走る（アクションで MOVE 分をもう一度移動）
  - ボスなど毎ターン 2〜3 回行動する敵: 手番の欄の「毎ターンの行動回数」
  - その場の裁定で 1 回だけ増やす: 「+1 アクション（このターンだけ）」
  - ネットランナーの NET アクション（インターフェイスの値で 2〜5 回）は、ネットランの機能がないため対象外

> ルールの数値（DV 表、致命傷表、修正値、価格カテゴリ）はコードに直接書かず、DB の「ルール定数」テーブルに置く。GM が版の差分やハウスルールを編集できるようにする。

### 5.2 商店

武器・防具・サイバーウェア・ギアなどを **価格と画像つき** で一覧・検索・購入する。

**カタログ**
- カード表示（画像・名称・価格・主要性能）と表表示を切り替えられる
- フィルタ: カテゴリ（武器／防具／サイバーウェア／ギア／衣服／弾薬／改造パーツ／プログラム／乗り物／ドラッグ）、価格カテゴリ、武器種別、隠匿可否、品質、出典、データ確認状態
- 並び替え: 価格、名称、ダメージ、SP
- 詳細: 全性能、要約説明、出典（英語版 p./日本語版 p.）、画像（複数可）、サイバーウェアの人間性損失や取り付け場所
- 価格カテゴリの表示（安価 10eb／日用 20／やや高価 50／高級 100／高価 500／超高価 1000／贅沢 5000／超贅沢 10000+）。境界値と名称は GM が日本語版の訳語に合わせて設定する

**店舗**（GM が作成）
- 店（例: ナイトマーケット、故買屋、クリニック）ごとに、在庫（取り扱う品と数量）、価格倍率、品揃えのカテゴリを設定する
- 「全カタログ」モードと「この店の在庫だけ」モードを切り替えられる

**購入・売却**
- カートに入れた品を、購入する PC を選んで確定すると、所持金（eb）を減らして所持品に追加する。在庫も減らす
- 値引き交渉の結果は GM が価格を手で上書きする（取引技能の判定は GM がリアルダイスで行う）
- 売却: GM が設定した買取率で eb を戻す
- 取引の履歴を保存する

**画像**
- 優先順位: ① GM が登録した本のスキャン画像（visibility に従う）→ ② GM がアップロードした画像 → ③ FVTT のアイコン（CC-BY）→ ④ カテゴリの既定アイコン
- 画像の登録: スマホで撮影または画像ファイルをアップロードし、ブラウザ上でトリミングしてアイテムに紐付ける。出典とページを記録する

### 5.3 シナリオ

GM が作る **シナリオメーカー** と、セッション中に使う **進行モード** の 2 つで構成する。AI による生成は行わない。

**シナリオメーカー（作成・編集）**
- シナリオの基本情報: タイトル、概要、推奨人数、想定時間、報酬、タグ
- **シーン**: タイトル、読み上げ文、GM メモ、場所、登場 NPC、手がかり、判定（技能・DV・成功時と失敗時の結果）、次のシーンへの分岐（条件つき）
- **フローチャート表示**: シーンをノード、分岐を矢印で描く。ドラッグで並べ替える。スマホでは一覧表示に切り替える
- **NPC**: DB の NPC を引用するか新規作成する（能力値・技能・装備・HP・SP・台詞メモ）。モブは人数を指定して量産できる
- **エンカウンター**: 敵の構成と初期配置メモ。ボタン一つで戦闘タブに投入できる
- **店舗**: シナリオ内の店を商店タブの店舗と紐付ける
- **ハンドアウト**: 画像・文章。プレイヤー端末への公開・非公開を切り替えられる
- **ランダム表**: GM が自作する表（d6、d10、2d6 など）。リアルダイスの出目を入れて結果を引く
- **テンプレート**: 「依頼 → 調査 → 潜入 → 戦闘 → 報酬」などの雛形から作り始められる
- エクスポート／インポート（JSON）、複製、バージョン履歴（保存のたびにスナップショットを残す）

**進行モード（セッション中）**
- 現在のシーンを表示し、分岐を選んで次のシーンへ進む
- 手がかり・ハンドアウトをプレイヤーへ公開する
- セッションログ: 時刻つきメモ、戦闘ログ、取引ログ、獲得報酬・経験点（IP）
- 予定外の出来事は「臨時シーン」としてその場で追加できる

### 5.3.1 ステージ（盤面）（2026-10-20 ユーザー決定。GM ウィンドウのシナリオ進行で操作）

- シナリオやシーンに **背景画像**（場所の絵、マップ、NPC の顔、ハンドアウト）を登録しておく。進行中にサムネイルを **クリックすると共有画面とプレイヤーのスマホに表示** する
- 背景の上に **コマ**（PC・NPC・モブ）を置き、ドラッグで動かす。コマは DB のキャラクターと紐付き、戦闘の参加者になる
- **グリッド**: 表示の有無、1 マスの距離（既定 2m）、背景に合わせた位置とサイズの調整
- 距離の計測、コマごとの「GM のみ表示」（隠れている敵など）、視界を隠す（未公開の範囲を黒で覆う）
- 「戦闘開始」で、盤面のコマをそのまま戦闘に入れ、行動順を自動ロールする
- **建物・障害物**（壁、木箱、コンテナ、車両など）は盤面のオブジェクトとして置く。属性は「通れるか」「射線を遮るか（全部 / 一部）」「遮蔽物の HP」。戦闘外ではドラッグで移動・サイズ変更・回転ができ、**戦闘中は固定** する
- **コマ（PC・NPC）** は、戦闘外では自由にドラッグできる。戦闘中は移動アクションの範囲内でだけ動かせる（GM は強制移動できる）
- 盤面は **「別ウィンドウで表示」** ボタンで、独立したウィンドウに出せる（GM の 2 枚目のモニター用）
- シナリオメーカーで、シーンごとに背景・グリッド設定・コマの初期配置を保存できる

### 5.3.2 ストーリー進行（選択肢と行動判定）（2026-10-20 ユーザー決定。GM ウィンドウのみ）

- **この場面の選択肢**: シナリオメーカーでシーンごとに選択肢を用意する（例: A 説得 DV13 / B 裏口を探す 知覚 DV13 / C ハック（ネットランナーのみ）/ D 強行突破 → 戦闘）。各選択肢に「技能・DV・誰が選べるか・成功時と失敗時の結果（次のシーン、手がかり）」を持たせる。「プレイヤーに公開」で各スマホの行動画面に出す。その場で追加もできる
- **行動判定ボード**: 「誰が・何を（選んだ行動）・能力値 + 技能・DV・出目・合計・結果」を 1 行ずつ並べる。プレイヤーがスマホで選んだ行動は自動で行になる。自由記述の行動は GM が技能を選んで DV を決める。DV の目安（簡単〜伝説的）をボタンで出す（数値は日本語版で確認）
- 対抗判定（相手も振る）、全員で同じ判定（グループ）、GM が代わりに出目を入力、にも対応する
- 判定結果から、次のシーンへの移動や手がかりの公開をボタン一つで行う。すべてセッションログに残す

### 5.4 DB（GM のみ）

- 全エンティティの一覧と編集、CSV/JSON の入出力、FVTT の取り込み（[§8](#8-データ取り込み)）
- 確認状態（下記）の一括変更、未確認品の一覧
- キャラクター（PC）: 能力値、技能、HP、人間性/EMP、所持金、所持品、装着中のサイバーウェア、装備中の武器と防具

### 5.5 PC 管理（資金・人間性）（2026-10-20 ユーザー決定。GM のみ）

- PC ごとに、資金（eb）、人間性（現在 / 最大）と EMP、スマホの接続状態を並べる
- **資金を送る・引く**: 金額（50 / 100 / 500 / 1,000 / 5,000 か自由入力）と理由を入れ、PC ごとの ＋ / − か「全員に送る」「合計額を人数で分ける」で送る。プレイヤーのスマホに「GM から +500 eb — 依頼の報酬」と通知が出て、キャラシートの資金とログが変わる。マイナス（罰金・支払い）もできる。すべて「お金のログ」に残る
- **開始資金**: キャラ作成で使える金額は GM が設定する。**当面は空欄（未設定）**（2026-10-20 ユーザー決定。チュートリアルの金額を既定値にする案は保留、Issue #7）。未設定のあいだ、キャラ作成は使った金額だけ表示し、資金オーバーのチェックはしない。招待（Google サイト用コード・QR）とキャラ作成画面にこの金額が入る
- **人間性**（計算は docs/RULES_CHECK.md §6）: 最大人間性 = EMP × 10 − 導入したサイバーウェア 1 つにつき 2（ボーグウェアは 4）。サイバーウェアを入れると人間性が減る（作成時は固定値、作成後は GM が「振る / 固定値」を選ぶ）。現在の EMP = 人間性 ÷ 10（切り捨て）。EMP が下がると、EMP を使う技能の基本値も自動で下がる。人間性が低いときの警告（サイバーサイコ）とセラピーでの回復は日本語版で確認する
- 商店とキャラ作成のサイバーウェアには、価格の横に人間性の減少量を出す

### 5.6 技能一覧と成功率（2026-10-20 ユーザー決定。GM のみ）

- **技能一覧**: コアルールの技能（FVTT の `internal/skills` 63 種＋言語・土地勘・武術・楽器・科学の各種）を、区分（認識・身体・教育・戦闘・射撃・社会・技術など）で絞り込んで表示する。列: 技能名、能力値、区分、基本技能か、×2（上げるコストが 2 倍）か、何に使うか（GM が自分の言葉で書くメモ欄。ルールブックの文章は写さない）、出典ページ（英語版は FVTT、日本語版は照合して入れる）
- **計算方法**: 選んだ技能の式（能力値 + 技能 + 1d10 − 負傷 vs DV）、DV を超えれば成功、出目 10 / 1 の追加ロールを常に表示する
- **成功率**: 技能を選び、難易度（日常的 13 〜 非現実的 24。イージー・モード p.15。または数値入力）を選んで「各キャラの成功率を見る」を押すと、PC ごとに「式・必要な出目・成功率（%）」を並べる。成功率は出目 10 / 1 の追加ロールまで含めて正確に計算し、重傷・瀕死のペナルティは現在の状態から入れる。技能がないキャラは能力値だけで計算する
- 「この判定を判定ボードに追加」で、ストーリーの判定ボード（§5.3.2）に全員分の行を作る

### 5.7 保存と読み込み（2026-10-20 ユーザー決定。GM のみ）

- **名前をつけて保存**: いまの状態を、GM がつけた名前で保存する（例: 「倉庫街の取引 — 突入前」）
- 保存する内容: キャラ（能力値・技能・HP・SP・状態・致命傷・所持品・弾数・資金・人間性・画像）、シナリオの進行（シーン・選んだ選択肢・公開した手がかり・判定のログ）、戦闘中なら参加者・行動順・ラウンド・手番・盤面のコマと障害物の位置、お金のログ、商店の在庫、GM のメモ
- **セーブ一覧**: 名前・日時・中身の要約を並べ、読み込む / いまの状態で上書き / 名前を変える / ファイルに書き出す（.cpgm-save）/ 削除。ファイルからの読み込みもできる（別の PC に移すときやバックアップ用）
- **自動保存**: 結果を確定するたびと 5 分ごとに「自動保存」を上書きする。読み込む前にも、いまの状態を自動保存に残す
- 読み込むと、つながっているスマホのキャラシートも切り替わる
- セーブは GM の PC の `data/` の中だけに置く（git に入れない。外に送らない）

### 5.8 プレイヤーと持ちキャラ・シナリオの縛り（2026-10-21 ユーザー決定。Phase 5i）

**プレイヤーの流れ**: QR を読む → キャラを作る（GM がシナリオに決めた開始資金で装備を買う）→ GM が受け付ける → シナリオが始まったら行動画面で探索の技能・戦闘のボタンを使う。商店はいつでも開ける。続きから遊ぶときも QR を読み、自分のキャラを選ぶ。

- **プレイヤー（人）** を登録する。パスワードなし（§4 認証）。QR を読んだら「あなたは？」で自分の名前をタップするか、はじめての人は名前を登録する
  - スマホはこの人を覚えるが、記録は開いたアドレスごとに分かれる。GM の PC の IP は Wi-Fi で変わるので、別の Wi-Fi では名前をもう一度タップする
  - GM のキャラごとの再開 QR（Phase 5d）でも入れる。入ると、そのキャラの持ち主をスマホが覚える
- **持ちキャラ**: 1 人が複数のキャラを持てる。名前を選ぶと、自分のキャラと持ち主なしのキャラだけが並ぶ。持ち主なしのキャラを選ぶと、その人のキャラになる。スマホで作ったキャラは、GM が受け付けると作った人のキャラになる。GM は PC タブで持ち主を変えられる
- **自動で選ぶ**: 自分のキャラのうち、いま選べるのが 1 人だけなら、名前を選んだ時点でそのキャラが開く。持ち主本人なら、別のスマホで使っていたキャラでも GM の承認なしで取り直せる（別の Wi-Fi で記録が消えたとき用）。シートの「キャラを変える」で選び直せる
- **シナリオの縛り**: シナリオの進行中にスマホで選んだキャラ、進行開始時にスマホでつながっていたキャラ、進行中に作って受け付けたキャラは、そのシナリオに入る。クリアするまで、ほかのシナリオの進行中は選べず「〇〇が未クリアのため、〇〇以外では選べません」と出る。進行中のシナリオがないとき（キャラ作成・買い物）は選べる
  - GM のシナリオ進行の **「シナリオクリア」** で進行を終え、参加キャラの縛りを外す（キャラはそのまま残り、次のシナリオで使える）。**「中断」** は進行を終えるが縛りは残る
  - 全滅・中断などでクリアしないときは、GM が PC タブの「シナリオから外す」で 1 人ずつ外す
  - **続きから**（2026-10-21 ユーザー決定）: 中断したシナリオを選ぶと「続きから再開（前回: シーン名）」が出て、前回のシーンから再開する。公開した手がかり・ハンドアウト・ログもそのまま。「最初から始める」も選べる。クリアしたシナリオには出ない
- **ハンドルネーム**（2026-10-21 ユーザー決定）: 「あなたは？」で選ぶ名前はプレイヤーのハンドルネームで、キャラ名とは別に保管する。シートの役職の横に「プレイヤー: 〇〇」と出し、人違いに気づけるようにする
- **開始資金はシナリオごと**: シナリオメーカーでシナリオに開始資金を設定する。シナリオの進行中に作るキャラはその額を使い、未設定なら全体の設定（PC タブ）を使う。キャラ作成画面には、どのシナリオの開始資金かを出す

## 7. ルール計算エンジン

- `packages/rules`（純粋関数のみ。UI と DB に依存しない）にまとめる。単体テストを必須とする

## 12. キャラシートの受け渡し（2026-10-20 ユーザー決定）

### 12.1 GM の PC と同じ Wi-Fi 内（当日）
- GM の PC で起動した CyberPGM の QR コードから、プレイヤーがキャラ作成・キャラシート画面を開く。作ったキャラはそのまま GM の DB に入る

### 12.2 外から（事前作成）: Google サイト
- GM は CyberPGM から **キャラ作成ページの埋め込みコード（HTML + JavaScript を 1 つにまとめたもの）** を書き出し、Google サイトの「埋め込み > コードを埋め込む」に貼る
- コードに入れるもの: GM のメールアドレス、開始資金、作成方法、買える装備の範囲、装備カタログ（**名前・価格・性能の文字情報だけ。画像は一切入れない**。アイコンも本のスキャンも入れない）。他のプレイヤーのデータも入れない（2026-10-20 ユーザー決定）
- 装備の画像を見られるのは、自宅 Wi-Fi で QR から開いたときだけ（§12.1）
- Google サイトの公開範囲はプレイヤーだけに限定する（Google アカウントで閲覧者を指定）。サーバーも Tailscale も使わない
- プレイヤーは作成したキャラを **「GM に送る」** で送る。送り方は、GM のメールアドレスあてに、キャラデータ（JSON。画像を含む）を添付または本文に入れたメールを作る。GM は当日、CyberPGM の「キャラ受付」でファイルかコードを取り込む
- 取り込み時にアプリがルールの検証（能力値・技能のポイント、資金オーバー）をして、GM が「取り込む / 差し戻す」を選ぶ
- 作成途中のデータはプレイヤーのブラウザに保存する（閉じても続きから再開できる）

### 12.4 キャラ作成の手順（2026-10-20 ユーザー決定。Wi-Fi 版・Google サイト版共通）

1. **基本**: 画像、ハンドル、ロール（作成方法は GM の招待で決まる）
2. **能力値**: 作成方法に沿って割り振る。人間性 = EMP × 10 を表示する
3. **技能**: **プレイヤーが一覧から選んで取る**（GM は決めない）。区分で絞り込み、技能ごとに − / ＋ でレベルを決める。各技能に「能力値 + レベル = 基本値」を出す
   - **ポイント数・レベルの上限・基本技能の最低レベル・×2 のコストは、GM が指定した作成方法のルールどおり**（2026-10-20 ユーザー決定）。値は日本語版で確認して `rule_constants` に置き、アプリが検証する（Issue #7）
   - 技能の上に「技能判定の計算方法」（基本値 = 能力値 + レベル、基本値 + 1d10 が DV を超えれば成功、10 / 1 の追加ロール、対抗判定、負傷の修正）を開閉式で出す
   - 技能名をタップすると、その技能の **使う場面**（1〜2 文）、**式**（例: DEX 6 + 回避 6 = 12 + 1d10）、**成功の目安**（例: 普通の DV 13 なら出目 2 以上で成功・90%）、基本技能 / ×2 の説明、出典ページを出す（2026-10-20 ユーザー決定）
   - 「使う場面」の文章は自分の言葉で短く書いたもので、ルールブックの文章は写さない。GM の技能画面（§5.6）のメモと同じデータを使い、GM が編集できる（Issue #20）。Google サイト版にも入れる（文字だけなので可）
4. **装備**: GM が設定した開始資金の範囲で買う（当面は空欄。未設定なら資金のチェックはしない）。サイバーウェアには人間性の減少量（作成時は固定値）を出し、買うと人間性と EMP がその場で変わる
5. **送信**: 能力値・技能ポイント・資金のチェックを出して GM に送る

### 12.3 実装前に検証すること（Phase 4 の最初に agy が試作で確認する）
1. Google サイトの埋め込みに入れられるコードの **サイズ上限**（文字だけの装備カタログが入るか。入らなければカタログを絞るか、分割する）
2. 埋め込み（sandbox の iframe）の中で、**メール作成（`mailto:`）・ファイル保存・Web Share API・画像の選択と撮影・ブラウザへの保存** が動くか（iPhone の Safari と Android の Chrome の両方）
3. 個人の Google アカウントで、サイトの閲覧者を **特定の人に限定** できるか
4. 動かない機能があった場合の代わり: キャラデータを短いテキストコードにして、メール本文やコピーで送る
