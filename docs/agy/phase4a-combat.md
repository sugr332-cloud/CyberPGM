## ゴール

GM 画面の **戦闘タブ** で、参加者を選んで行動順を決め、手番ごとに行動ボタンから手順の案内に沿って出目を入れると、ルールエンジンが結果を出し、GM の「確定して反映」で HP・SP・弾数・状態が GM 画面とプレイヤーのスマホに同時に反映される。

Phase 4 は 2 つに分ける。

- **4a（この指示書）**: 参加者チェック、行動順、参加者カード、ターン進行ガイド、判定と結果の反映、取り消し、戦闘ログ、プレイヤーの行動画面
- **4b（次）**: 盤面（マス・コマ・移動・壁・射線・遮蔽物）、戦闘の別ウィンドウ `/gm/combat`、TV の共有画面 `/screen`

4a では盤面がないので、**距離は GM が数値（m）で入れる**。4b で盤面から自動で測るように差し替える。SPEC §12.3（Google サイトの検証）は Phase 6 で扱う（Issue #19）。

## 1. データ

### 1.1 行動の説明文（Claude が用意した。改変しない）

- `docs/data/combat-actions.ja.json` を `rule_constants` の `combat_actions` に入れる（シードと、起動時に未登録なら入れる。Phase 3b の skill-notes と同じ扱い。**GM が編集した値は上書きしない**）
- 各行動: `key`、`label`、`slot`（move / action / reaction）、`status`（confirmed / unconfirmed）、`issue`、`desc`
- 文の言い回しを agy が書き換えたり、足りない文を作ったりしない。足りなければ報告に書く

### 1.2 戦闘の状態（drizzle のマイグレーションを追加）

| テーブル | 列 |
|---|---|
| `combats` | id, status（setup / active / ended）, round, turn_index, settings(JSON), created_at, ended_at |
| `combat_participants` | id, combat_id, character_id null, side（ally / enemy）, name, initiative, initiative_roll(JSON), order_index, active（参加・不参加）, out（死亡・離脱）, move_used, action_used, state(JSON) |
| `combat_log` | id, combat_id, round, actor_id, action_key, input(JSON), breakdown(JSON), changes(JSON), undone, at |

- **HP・SP・弾数・状態（`status`）・致命傷（`crit_injuries`）は `characters` の値を正本にする**（戦闘用に複製しない。PC のキャラシートと同じ値を書き換える）。`combat_participants.state` には戦闘の中だけの値（遮蔽中、落とした物とそのマス、状態の残りラウンド、死亡セーブのペナルティ）を持つ
- NPC・モブ: `characters.kind = 'npc' | 'mook'`。いまの DB には 0 件で、FVTT にも NPC のデータはない。GM が **PC タブで NPC・モブを作れる** ようにする（名前、ロール、能力値、HP の最大、SP、武器・防具はカタログから選ぶ、画像）。**シードに NPC の数値を作って入れない**（E2E では一時 DB にテスト用の NPC を作る）
- モブの人数を指定して参加させたら、元のモブを複製して「○○ #1」「#2」…を作る（戦闘の終了時に複製を消すかを GM が選ぶ）
- 武器: FVTT の武器データの `fireModes.suppressiveFire` が取り込まれていないので、`weapons` に列 `suppressive` を足して取り込み直す（`autofire` と同じ扱い。GM が編集した列は上書きしない）。**本番の DB への取り込み直しは agy が行わない**（マージ後に Claude が行う）。テストでは一時 DB で確かめる
- 保存ファイル（cpgm-save）の `version` を 3 に上げ、戦闘の 3 テーブルを含める。version 1・2 も読めるようにする

## 2. 戦闘開始: 参加者チェックと行動順（モック「GM — 戦闘開始」）

- 戦闘タブの「戦闘を始める」で参加者チェック画面を出す
  - PC 全員を、サムネイル・名前・HP・状態つきで並べ、チェックで参加・不参加を切り替える
  - 「NPC を追加」（DB の NPC 一覧から）、モブの人数指定、味方 NPC（side を ally にする）
  - サムネイル: キャラの画像。なければ頭文字を味方色（`#4FB6E3`）・敵色（`#F28C38`）で
- 右側に行動順（REF + 1d10。`packages/rules` の `initiativeTotal` / `sortInitiative`）
  - NPC は自動ロール。PC は「スマホかこの画面で出目を入力」。設定で「全員自動」に切り替えられる
  - 入力待ちの PC を表示する。プレイヤーのスマホの行動画面に「イニシアチブの出目を入力」を出す
  - 同値の扱いは GM 設定（RULES_CHECK §2「同値の順番」は要確認）。既定は「REF の高い方 → それも同じなら振り直し」をボタンで GM が行う
  - ドラッグで手直しできる
- 「行動順を確定して戦闘開始」で戦闘画面へ

## 3. 戦闘画面（モック「GM — 戦闘」。盤面の場所は 4b まで空けておく）

- 上部に **行動順バー**: サムネイル・名前・イニシアチブ、手番中の強調、重傷・瀕死の印、死亡・離脱はグレーで手番を飛ばす。ラウンド数
- 左に味方、右に敵の **参加者カード**（SPEC §5.1 の項目すべて）。HP バーは味方色/敵色 → 黄=重傷 → 赤=瀕死。カードをタップで詳細（全能力値・全技能・所持品・サイバーウェア）
- 武器の性能は DB どおり。**値がない項目は「—」**（Phase 3a の指摘と同じ）
- 手番は「手番を終える」で次へ。全員終わったらラウンド +1、状態の残りラウンドを 1 減らす。途中参加は自動ロールして差し込む
- スマホ幅（390px）では行動順バーの下で「味方 / 敵」をタブで切り替える

## 4. ターン進行ガイド（GM 画面のみ）

- 手番が来たら「**○○のターンです**」と大きく出し、`combat_actions` の行動をボタンで並べる。移動アクションとアクションの使用状況を出す
- 使えない行動はグレーにして理由を出す。**判断は武器のデータで行う**（武器名で分岐しない）: オートファイアは `weapons.autofire`、制圧射撃は `weapons.suppressive` があるときだけ、射撃・照準射撃は射撃武器を持っているときだけ、リロードは予備の弾があるときだけ、など
- ボタンを押すと、まず **説明文**（§1.1 の `desc`）を出す。続けて手順
- `status: unconfirmed` の行動は、手順の上に「ルール確認中（Issue #n）。結果は GM が入力」と出し、**自動で計算しない**。GM が HP・状態などの変化を手で入れる欄を出し、それも同じ「確定して反映」に通す
- `status: confirmed` の行動の手順:
  - **対象の選択欄**: 敵の名前ボタン。距離（m）を GM が入れる（4b で盤面から自動）
  - **計算式と成功ライン** を押す前から出す（SPEC §5.0.1 の例どおり。表記は「難易度」。重傷・瀕死のペナルティ、照準 −8 も式に入れる）
    - 射撃: 武器種別の DV 表（`rule_constants` の `dv_table.*`。`rangedDv`）。DV 表がない・距離が範囲外なら「射程外」と出す
    - 対象が射撃を回避できるとき（`canDodgeRanged`。REF 8 以上は要確認 #2 なので、`rule_constants` の値を使う）は「難易度で受ける / 回避で受ける」を GM が選ぶ
    - ROF 2 は 2 回の判定を順に出す（`attacksPerAction`）
    - 照準射撃: 部位（頭部 / 持っている物 / 脚）を選ぶ。持っている物を選んだら対象の装備中の所持品から選ぶ
    - オートファイア: オートファイア用の DV 表、倍率（`autofireMultiplier`。上限は武器のデータ）
  - **出目の入力**: 「出目を入力」（既定）と「アプリで振る」。10 と 1 のときは追加の出目を求める。攻撃する側が PC なら、スマホの行動画面から届いた出目が入る（§6）。GM 側には「○○のスマホから入力 / 入力待ち」と出し、GM が代わりに入れてもよい
  - **ダメージ**: ダメージダイスの各出目を入れる（`resolveDamage`）。クリティカル（6 が 2 個）は致命傷表の出目（2d6）を求め、`lookupCriticalInjury` で結果を引く。致命傷の名前・説明は FVTT のデータどおり出す（日本語の訳がなければ英語のまま。**訳を作らない**）
  - **死亡セーブ**: 瀕死の参加者の手番の初めに「死亡セーブ」を出す（`deathSave`）

## 5. 結果の反映と取り消し（SPEC §5.0.1）

- 出目がそろったら、手順の下に **「反映する内容」** を一覧で出す（例: 「ガンガー #2 HP 25 → 11」「状態 重傷（−2）になる」「SP 胴 7 → 6」「ヴァイパー 弾 6/8 → 5/8」）
- **「確定して反映」** で 1 トランザクションで書き換える: HP、SP（頭/胴）、弾数、状態、致命傷、落とした装備（所持品の `equipped` を外し、`state` に「落とした物」として記録。拾うと戻す）。重傷・瀕死・死亡は HP から自動で付け外しする（`woundState`）
- 反映先: GM の戦闘画面、該当プレイヤーのスマホ（`me:update` と通知）。すべて同じ確定結果から書く
- **「取り消す」**: 直前の確定を元に戻す（`combat_log.changes` に変更前の値を持ち、逆に適用する。`undone` を立てる）。何回でも遡れる
- 戦闘ログ: ラウンド・誰が・何を・内訳・変化。戦闘タブの下に出す。「戦闘を終える」で `combats.status = ended`
- 計算は **すべて `packages/rules` の関数** で行う（画面やサーバで式を書き直さない）

## 6. プレイヤーの行動画面（`/player/act`。モック「プレイヤーのスマホ — 行動」）

- 戦闘中だけ戦闘の行動を出す。キャラシートとの切り替えは下部のタブ
- 自分の手番のときだけ行動ボタンを押せる。それ以外は「○○の手番です」と出す（他人の数値は出さない）
- ボタンには GM 側と同じ計算式と成功ラインを出す（自分の値と、選んだ対象の難易度。敵の数値は出さない設定が既定なので、対象の名前と距離帯の難易度だけ）
- 選ぶと GM のターン進行ガイドに届く（GM が手順を開く）。出目パッド（大きな数字ボタン、片手で押せる）で出目を送る。10 と 1 は追加の出目
- 「回避（GM に言われたとき）」は手番でなくても押せる
- 「イニシアチブの出目を入力」は参加者チェック中に出す
- 上部に「GM が確定した結果」、攻撃を受けたらキャラシートの上に赤い通知（SPEC §5.0.1 の例どおり）
- キャラシートの HP・SP・弾数・状態・致命傷が自動で更新される。重傷などのペナルティは技能の基本値と行動ボタンの成功ラインに自動で入る
- キャラシートの下に自分に関係するログ

## 7. API・WebSocket（入出力は zod）

- `POST /api/combats`、`GET /api/combats/current`、`PATCH /api/combats/:id`（設定、手番、終了）
- `POST /api/combats/:id/participants`、`PATCH/DELETE .../participants/:pid`、`POST .../initiative`
- `POST /api/combats/:id/resolve`（出目と選択 → 内訳と「反映する内容」を返す。**DB は変えない**）
- `POST /api/combats/:id/apply`（確定。内訳を再計算して書き込む。クライアントの計算結果をそのまま信じない）
- `POST /api/combats/:id/undo`
- WebSocket: `combat:update`（GM 全員）、プレイヤーには自分の分だけ（`me:update`、`combat:turn`、`combat:result`）。player は他の参加者の数値を受け取らない（既存の権限分けを維持）
- player から: `combat:choose`（行動の選択）、`combat:roll`（出目）。自分の手番・自分のキャラ以外は 403

## 8. テスト

- 単体・結合

## 11. レビュー指摘 02（2026-10-20 Claude。同じブランチで直して報告 02 を出す）

画面の流れ（参加者チェック → 行動順 → 手番 → 反映 → 取り消し）、確定時にサーバで計算し直す作り、権限の分け方はよくできている。ただし **計算に作り話の値が入っていて、技能値も弾数も正しく反映されていない**。スクリーンショットの「REF 8 + 技能 0」がその証拠（ヴァイパーの拳銃は 6）。次を直す。

### 11.1 【最優先】作り話の値を消す（指示書冒頭「ルールの数値を推測で入れない」違反）

`combat-resolver.ts` の次をすべて削除する。値がなければ **計算せず、何が足りないかを画面に出す**（「武器の DV 表がありません」「距離を入れてください」「出目を入れてください」）。

- DV 表の既定値 `[0-6:13, 7-12:15, 13-25:20, 26-50:25, 51-100:30]`
- `'dv_table.Pistol'` への逃げ、`wData?.skill || 'Handgun'`、`'射撃武器'`
- 距離の既定 `?? 5`、出目の既定 `: 1`（攻撃・防御）、ダメージの既定 `[1,1,1]` / `[1,1]`
- オートファイアの倍率上限の既定 `?? 3`、弾数 `isAutofire ? 10 : 1` の 10（Issue #6 で確認中。オートファイアの弾数は GM が入れる欄にする）
- 近接の `ignoreArmorPercent: 50` の固定（下の 11.4）

### 11.2 オートファイアの DV 表のキーが存在しない

`'dv_table.Autofire'` という定数はない。FVTT は武器の `dvTable` に ` (Autofire)` を付けた表を使う（`cpr-loadable.js` 43 行目）。`dv_table.${weapon.dv_table_key} (Autofire)` を引く。表がなければ「オートファイアの DV 表なし」で止める。テスト: アサルト・ライフルのオートファイアで `DV Assault Rifle (Autofire)` が使われる。

### 11.3 技能値が 0 になる（キーの食い違い）

`characters.skills` のキーは `handgun`・`evasion` のような小文字のキー。`weapons.skill` は `Handgun`・`Shoulder Arms` のような英語名。`skills['Evasion']`・`skills['Melee Weapon']` も同じく 0 になる。Phase 3b の技能カタログ（`packages/shared` の SKILL_CATALOG）で英語名からキーに変換する関数を **1 つ** 作って全箇所で使う。テスト: ヴァイパー（REF 8・拳銃 6）の射撃の基本値が 14、ニクスの回避が DEX + evasion になる。

### 11.4 近接の防具無視率は武器のデータで

FVTT の武器に `ignoreArmorPercent` がある（アサルト・ライフルは 0、近接武器は 50）。`weapons` に列 `ignore_armor_percent` を足して取り込み、その値を `resolveDamage` に渡す（指示書 §4「武器のデータで分岐する」）。近接攻撃の技能も武器の `skill` から取る。素手の格闘（`brawl`）は unconfirmed のまま手入力。

### 11.5 弾数が減っていない

`apply` に `ammo` の処理がなく、変化も「-1発」という文字列で、どの値も書き換わっていない（報告の「E2E で弾数減少を検証」は `e2e/combat.spec.ts` に該当の確認がない）。

- 所持品の武器の行（`inventory` の entry）に `ammo`（現在の弾数）を持たせる。未設定なら `weapons.magazine_max`（それもなければ「—」で、弾数のチェックをしない）
- 射撃で `before` / `after` を数値で記録して書き換える。取り消しで戻す。弾が足りなければ撃てない
- リロード（confirmed）: 弾数を `magazine_max` に戻す。予備の弾の消費は Phase 3a の所持品の弾薬から 1 つ減らす（弾薬の種類の一致は見ない。報告に書く）
- 射撃・照準射撃では、撃つ武器を **その参加者の装備中の武器から選ぶ欄** を出す（いまは `weapon_id` がなく 1 種類に決め打ち）
- テスト: 射撃 → 8/8 が 7/8、取り消しで 8/8、リロードで満タン。E2E でスマホのキャラシートの弾数が変わる

### 11.6 出目 10 / 1 の追加ロールを求めていない

### 11.7 ROF 2 が 1 回しか撃てない

`attacksPerAction` を使い、ROF 2 の武器は 2 回分の判定（出目・ダメージ）を順に出す（指示書 §4）。テスト: 大型拳銃（ROF 2）で 2 回分の変化がまとめて反映され、弾が 2 減る。

### 11.8 致命傷

### 11.9 プレイヤーに敵の数値を送っている

スマホの「行動結果」に「ガンガー #1 HP 25 → 13」「SP 胴 7 → 6」が出ている。指示書 §6・SPEC §5.0.1 の既定は **敵は名前と負傷状態だけ**。プレイヤーに送るのは、自分の変化（HP・SP・弾数・状態）と「命中 · ガンガー #1 に 12 ダメージ → 重傷」の形だけにする（与えたダメージは見せてよい。HP・SP の数値は見せない）。サーバ側で出し分ける。テスト: player が受け取る `combat:result` に敵の `hp` / `sp` が入っていない。

## 12. レビュー指摘 03（2026-10-20 Claude。同じブランチで直して報告 03 を出す）

報告 02 で、技能値（REF 8 + 拳銃 6）、弾数 8/8 → 7/8、オートファイアの DV 表、ROF 2、致命傷の出目、敵の数値を隠すのは直った。テストも項目ごとにあってよい。残りは次の 4 点。

1. **残っている作り話の既定値**: `magazine_max ?? 8`（リロード）、`wData.autofire ?? 3`、近接の `ignore_armor_percent ?? 50`、取り込みの `isRanged ? 0 : 50`。値がなければ、弾数は「—」でチェックしない・リロードは「装弾数が不明」で止める、オートファイアは「倍率の上限が不明」で止める、防具無視率は FVTT の値をそのまま（なければ null で、近接攻撃の手順に「防具無視率が不明。GM が入力」の欄を出す）
2. **予備の弾を名前で探している**（`'弾'`・`'ammo'`・`'bullet'` を含む名前）。品目の `kind = 'ammo'` で探す。**予備の弾がなければリロードできない**（指示書 §4。いまは予備がなくても満タンになる）。テスト: 予備なし → リロード不可、予備 1 → リロードで 0 になり所持品から消える
3. **武器の選択欄と計算する武器がずれている**: 選択欄は「ヘビー・ピストル（残弾: —）」なのに、計算は所持品の「大型拳銃 8/8」で行っている。選択欄は **所持品のうち `kind = 'weapon'` の行**（entry_id・名前・残弾）から作り、選んだ entry で計算する。`characters.weapons` の文字列（品目 ID のないもの）は計算に使えないので、選択欄に出さない（カードの表示はそのままでよい）
4. 報告 03 に、直した項目ごとのテスト名を書く
