# agy 運用ルール（指示書と報告のやり取り）

Claude（仕様・指示書・レビュー担当）と agy（実装担当）が、ユーザーを介した長文のコピペなしでやり取りするための場所。

Claude が利用上限で動けないときは、Codex が Claude の役割（指示書・監査・マージ）を引き継ぐ。手順は [AUDIT.md](AUDIT.md)（2026-10-24 ユーザー決定）。

## 流れ

1. Claude が指示書を `docs/agy/<フェーズ名>.md` として main に push する
2. ユーザーが agy に「docs/agy/<フェーズ名>.md を読んで実行して」と伝える
3. agy は main を pull し、作業ブランチ `agy/<フェーズ名>` を切って実装する
4. agy はコードと報告 `docs/agy/reports/<フェーズ名>-<連番>.md` を作業ブランチに commit・push する
5. ユーザーが Claude に「報告来た」と伝える
6. Claude がブランチをレビューする。OK なら main にマージし、修正が必要なら指示書を更新して push する
7. ユーザーが agy に「OK、続けて」または「指示書が更新された。読み直して」と伝える

## agy の起動

LivingPC で、リポジトリのルートから次のように起動する。シェルの `agy` エイリアスには `--dangerously-skip-permissions` が付いているので、`command agy` でエイリアスを回避する。

```
command agy --mode accept-edits --model gemini-4-argon-high
```

2026-10-22 から実装は Gemini 4 Argon（High）が行い、Claude は指示と監査だけ（ユーザー決定）。`claude-*` モデルは使わない。

## agy が止まる場面（この 3 つだけ）

次のどれかに当たるときは、実行する前に報告ファイルを push して止まり、ユーザーの「OK」を待つこと。

1. **元に戻せない操作**: リポジトリ外のファイル削除、`data/` の既存 DB の削除・作り直し、systemd などシステム設定の変更
2. **外部への公開**: 0.0.0.0 での待ち受け、ポート開放、外部サービスへのアップロード
3. **仕様・指示書にないこと**: docs/SPEC.md や指示書と食い違う、書かれていない判断が必要、前提が満たされていない

それ以外の、仕様と指示書の範囲内の作業は止まらずに進めてよい。ただし、何をしたかは報告ファイルにすべて記録する。

## 常に守ること

- docs/SPEC.md §3（権利・ライセンス方針）を守る。ルールブックの本文・スキャン画像・取り込んだ DB・FVTT のファイルは **commit しない**（`data/` は git 管理外）
- 個人データ（ブラウザ履歴・Cookie・パスワード・アカウント）には一切アクセスしない
- 個人のパスやユーザー名をリポジトリに書かない（`<HOME>`、`<FVTT_REPO>` のように伏せる）
- 指示書にない npm パッケージを追加するときは、報告に名前と理由を書く
- push してよいのは作業ブランチ `agy/<フェーズ名>` だけ。main への push・マージ・force push はしない
- commit メッセージは日本語でよい。1 つの commit には 1 つの目的だけを入れる
- 画面を実装するときは、docs/SPEC.md §10「UI モックと UI 調整」に従い、承認済みモックに合わせる。報告には PC 幅（1440px）とスマホ幅（390px）のスクリーンショットを `docs/agy/reports/img/` に置いて貼る
- 完了報告の前に `npm run lint`、`npm run typecheck`、`npm test` を通す。結果を報告に貼る

## 報告ファイルの書き方

`docs/agy/reports/<フェーズ名>-<連番>.md`（例: `phase0-scaffold-import-01.md`）

```
# <フェーズ名> 報告 <連番>

- 日時:
- 使用モデル:
- 状態: 停止中（OK 待ち）/ 進行中 / 完了
- 停止した理由: （止まる場面の 1〜3 のどれか。完了なら「完了」）

## 実施したこと

## 確認した事実（コマンドと出力）

## 次にやること（OK が出たら実行すること）

## 問題・仕様との食い違い
```
