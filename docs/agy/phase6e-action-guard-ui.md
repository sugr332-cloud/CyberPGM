## A. 使えない行動は押せなくし、理由を出す

- `apps/server/src/services/combat-resolver.ts` の `actionBlockReason` に足す:
  - `martial_arts`（武術攻撃）と武術の奥義: どの流派の〈武術〉も 1 未満なら「〈武術〉を 1 レベル以上修得していないと使えません（p.178）」
  - `first_aid`（応急手当）: 〈応急手当〉も〈救急医療〉も 0 のときの扱いはルール上禁止されていない（技能 0 でも判定はできる）ので、**押せなくしない**
  - ほかに、技能や装備が前提の行動で、今の可否判定から漏れているものがあれば同じように足す（例: 近接武器を持っていないのに近接武器攻撃、遠隔武器がないのに射撃）。足したものは報告に一覧で書く
- この理由は `/api/combat-availability` を通して GM 画面とスマホの両方に届いている（Phase 6a）。**GM の戦闘画面でも**、行動のボタン・選択肢を同じ理由でグレーにして押せなくし、理由を表示する（スマホは Phase 6a のとおり）
- サーバー側でも、押せない行動が送られてきたら同じ理由で断る（今の `apply` の流れに合わせる）
- 単体テスト: 〈武術〉0 のキャラの `martial_arts` が断られる、1 以上なら通る

## B. 判定で足りない入力を赤枠で示す

- GM の判定欄（攻撃・回避・ダメージ・追加ロール・致命的損傷・死亡セーヴなど）で、計算に足りない入力（`missing_inputs` に出るもの）があるとき、**その入力欄を赤い枠で囲む**
  - どの欄が足りないかは `missing_inputs` の文言から推測せず、欄ごとの識別子（例: `attack_roll`、`defense_roll`、`damage_rolls`、`crit_roll`、`death_save_roll`）で返すようにして、それを使う。既存の `missing_inputs`（文言）は残す
  - 対象の未選択・武器の未選択など、入力欄ではないものも、その選択欄を赤枠にする
  - 入力されたら赤枠は消える
- スマホの出目入力も、足りないものがあれば同じく赤枠にする
- 色は既存の警告色（`var(--color-warning)` など、テーマにある赤系）を使う。ダークモードでも見えること

## C. 格闘・武術にもダイス数を出す

- Phase 6d で、武器には「2d6」などが出るようになった。**行動のボタン・選択肢そのもの**にも出す:
  - GM 画面とスマホの「格闘（素手）」「武術攻撃」のボタンに、そのキャラのダメージ（例: `格闘（素手） 2d6`、`武術攻撃 3d6`）
  - 値は Phase 6d の `combatDamageFormula`（`packages/shared/src/combat-damage.ts`）を使う。新しく計算しない
- 出目欄の近くの「ダメージ: 2d6（6 面ダイスを 2 個）」は、格闘・武術を選んだときも出ること（GM・スマホとも）

## D. 車両の行動は「車両」ボタンの中にまとめる

- 今は「乗る」「降りる」などの車両の行動が、ほかの行動と並んでいる
- GM 画面とスマホの行動の一覧に **「車両」ボタンを 1 つ** 作り、それを押すと車両の行動（乗る・降りる・始動・操縦・特殊機動・体当たり・車両への攻撃など、今ある車両の行動すべて）が出るようにする。戻るボタンでもとの一覧に戻る
- 車両に乗っていないときは「乗る」だけが押せ、ほかは理由付きでグレー（A の仕組みを使う）
- 車両の行動の中身・計算は変えない

## E. 振るダイスを、選んだ行動に合うものだけにする

ユーザーは「振るダイスに全部回避とか攻撃とかある」のが分からないと言っている。

- 今の画面（GM の判定欄、スマホの出目パッド `padRollType`）を見て、**選んだ行動に関係ない出目欄・種類が出ていないか**確かめ、関係あるものだけにする。例:
  - 格闘・射撃: 「命中の判定（1d10）」と、命中したら「ダメージ（2d6）」。相手の「回避（1d10）」は、相手が回避するときだけ（相手側の欄として、誰が振るか分かるように）
  - 応急手当: 「応急手当の判定（1d10）」だけ。回避・ダメージは出さない
  - 死亡セーヴ: 「死亡セーヴ（1d10）」だけ
- 欄の名前は「攻撃 1d10」ではなく、**何のために・誰が振るか**が分かる言い方にする（例: 「命中の判定 — 〇〇が 1d10」「回避 — △△が 1d10（遠隔攻撃は〈回避〉が REF 8 以上のときだけ）」）
- スマホの出目パッドは、選んだ行動に合わせて種類が自動で決まり、プレイヤーが「攻撃／回避」を選び直さなくてよいようにする（GM に言われて回避するときは、今のとおり「回避」ボタンから）
- 変えたところと、変える前の表示を、報告に表で書く

## G. 追加（2026-10-23）: すべての行動で、出目の欄をその行動に合うものだけにする

ユーザー:

> この辺りも、書くスキルに対応したダイス入力になってるか確認せよ。おそらく、すべてなっている。

Claude が確かめたところ、GM の判定欄は「出さない行動」を除外する作りで（例: `CombatView.tsx` の「受け方」は `!MELEE_LIKE.includes(...) && !['choke', 'throw', 'hazard', ...]`）、除外に入っていない行動では、攻撃・回避・ダメージ・致命傷の欄がすべて出る。応急手当はその一例。

- **行動ごとに必要な入力を決めた表**（行動のキー → 出す欄・誰が振るか・ダイス・欄の名前）を 1 か所（`packages/shared` など）に作り、GM の判定欄とスマホの出目パッドの両方がその表から欄を出すようにする。除外の並べ方はやめ、**表にある欄だけ**出す
- 対象は戦闘で選べる**すべての行動**（射撃・狙い撃ち・連射・制圧射撃・近接・格闘・武術・奥義・つかむ・締める・投げる・物を投げる・回避・応急手当・死亡セーヴ・薬物・環境ダメージ・リロード・立ち上がる・遮蔽・車両の行動・NET アクション・ICE の攻撃・スキャナーなど、今ある行動のキーを全部列挙して漏れがないこと）
- 各行動で、必要な出目は**今の解決処理（`combat-resolver.ts`）が読む入力**と一致させる（解決処理が読まない欄は出さない。読む欄は必ず出す）。表と解決処理がずれていないことを単体テストで確かめる（行動ごとに、表にない入力を送っても計算が変わらない、表の入力が欠けたら `missing_inputs` が出る）
- 「受け方（難易度か回避か）」は、ルール上どちらも取りうる遠隔攻撃だけに出す
- 報告に、**全行動の表**（行動・出す欄・誰が振るか・ダイス）と、変更前に余計な欄が出ていた行動の一覧を書く
- E2E: 代表として 応急手当・死亡セーヴ・格闘・射撃・環境ダメージ・車両の行動 1 つで、出る欄が表のとおりであること
