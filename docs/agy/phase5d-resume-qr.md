## 1. キャラごとの再開 QR（2026-10-21 ユーザー決定）

セーブデータから始めるとき、GM が **キャラごとの QR** を出し、プレイヤーがそれを読むだけで、そのキャラとしてすぐ再開できるようにする。

- **出す場所**
  - 「保存・読み込み」で読み込みが終わった画面に、PC ごとの QR を並べる（サムネイル・名前・QR）
  - PC タブの各 PC のカードにも「このキャラの QR」ボタン（いつでも出せる。読み込み直後でなくてもよい）
- **QR の中身**: `http://<LAN の IP>:8787/player?join=<今のセッションコード>&pc=<キャラ ID>`。セッションコードはサーバを起動し直すと変わるので、QR は表示するたびに今のコードで作る（保存ファイルに QR を入れない）
- **読んだとき**: 参加画面でキャラ選びを飛ばし、そのキャラに紐付けて、キャラシートを開く
  - そのキャラがほかの端末に紐付いていたら、Phase 2 の「端末の重なり」と同じく GM に確認を出す（勝手に奪わない）。GM が許可すれば新しい端末に移る
  - `pc` のキャラが存在しない・PC でない（NPC）なら、ふつうの参加画面（キャラ選び）に戻し、理由を出す
- **権限は今までどおり**: 紐付いたスマホは自分のキャラだけ。QR に新しい秘密の値（PIN・パスワード）を入れない
- 一覧の上に「全員分を印刷」（QR と名前を 1 枚に並べた印刷用の表示）。印刷はブラウザの印刷でよい

## 2. シナリオ取り込みの ID 付け替えの漏れ（Phase 5a の不具合）

`POST /api/scenarios/import` は、選択肢の結果のうち `next_scene` の `scene_id` だけを新しい ID に付け替えていて、`reveal_clue` の `clue_id` と `reveal_handout` の `handout_id` が元の ID のまま残る（取り込んだシナリオで手がかりが公開できない）。手がかり・ハンドアウトにも ID の対応表を作り、結果の参照を付け替える。エンカウンターの `scene_id` も同じく確かめる。テスト: 手がかりとハンドアウトを公開する選択肢を持つシナリオを書き出し → 取り込みで、参照が新しい ID を指す。

## 3. テスト

- QR の URL に今のセッションコードとキャラ ID が入る。サーバを起動し直すとコードが変わる
- 保存 → 読み込み → QR の URL でスマホが参加すると、キャラ選びなしでそのキャラのシートが開く
- 別の端末が紐付いているキャラの QR を読むと、GM に確認が出る。許可で移る・拒否で移らない
- 存在しない ID・NPC の ID ではキャラ選びに戻る
- player はほかの PC の QR の URL を作っても、紐付けは GM の確認なしに奪えない
- §2 の取り込み
- E2E: 保存 → 読み込み → GM の画面に PC ごとの QR → 1 つ目の URL をスマホ幅で開くとヴァイパーのシートが出る
- スクリーンショット: 読み込み後の QR の一覧（1440px）、印刷用の表示、QR から開いたスマホ（390px）
