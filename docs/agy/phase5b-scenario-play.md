## ゴール

GM がシナリオを選んで **進行モード** に入り、シーンを順に進められる。シーンの背景と盤面を TV とスマホに出し、選択肢をプレイヤーのスマホに公開し、プレイヤーが選んだ行動を **判定ボード** で判定して、結果（HP・状態・手がかり・次のシーンなど）を 4a と同じ「確定して反映」で反映できる。エンカウンターをそのまま戦闘に入れられる。

## 0. 持ち越し（最初に直す）

- **E2E が本番の画像フォルダに書き込んでいる**: `playwright.config.ts` の `webServer.command` に `IMAGES_DIR` がなく、E2E の画像アップロードが `data/images/user/` に入っていた（2026-10-20 17:43〜10-21 01:00 の 18 ファイル。Claude が削除済み）。E2E 用のサーバにも、`os.tmpdir()` の一時フォルダを `IMAGES_DIR` として渡し、終わったら消す。単体テストで「playwright の設定の `IMAGES_DIR` が `data/` の外を指す」ことを確かめる

## 1. 進行モード（シナリオタブ。モック「GM — シナリオ進行・盤面」）

- シナリオタブに「作る」と「進める」の切り替えを置く。「進める」でシナリオを選ぶと進行モード
- 進行の状態は `scenario_sessions`（id, scenario_id, current_scene_id, started_at, ended_at, revealed(JSON: clue_ids, handout_ids)）に持つ。同時に進められるのは 1 つ
- 画面: 左にシーンの一覧（今のシーンを強調、行ったシーンに印）、中央に今のシーン（読み上げ文・GM メモ・登場 NPC・場所）と背景・盤面、右に選択肢・判定ボード・手がかり・ハンドアウト・エンカウンター
- 「次のシーンへ」: そのシーンの `scene_links` をボタンで出し（条件の文字つき）、押すと移る。どのシーンにも移れる「ほかのシーンへ」も置く
- **臨時シーン**: 「臨時シーンを足す」でその場でシーンを作る（タイトルと読み上げ文だけ。シナリオ本体にも保存し、`scenes` に印 `is_adhoc`）

## 2. 背景・盤面・視界を隠す（SPEC §5.3.1）

- 背景: シーンの背景画像と、シナリオ内の画像のサムネイルを並べる。クリックで **TV とプレイヤーのスマホに表示**（`screen:update` と、スマホの新しい表示欄「GM からの表示」）。`visibility = gm`（本のスキャン）は出さず、Phase 4b と同じ警告を出す
- 盤面: シーンに盤面があれば 4b の `BoardView` を使って出す。シーンを切り替えると盤面も切り替わる。**シーンの初期配置**（コマの位置）は、その盤面の `board_tokens` として保存する
- **視界を隠す**: GM がマスをドラッグで塗って「隠す / 見せる」を切り替える（`boards.fog`(JSON: 隠すマスの一覧) を足す）。GM の盤面では半透明の黒、TV では真っ黒にして、隠れたマスのコマ・オブジェクトは **サーバ側で送らない**
- 「この盤面で戦闘開始」: 盤面のコマ（`gm_only` も含む）をそのまま 4a の参加者チェックに入れ、盤面つきで戦闘を始める

## 3. 選択肢と判定ボード（SPEC §5.3.2。モック「GM — ストーリー進行」）

- **選択肢の公開**: 5a の `scene_choices` を「プレイヤーに公開」でスマホの行動画面（ストーリー時）に出す。`who` に合うプレイヤーだけに出す。その場で選択肢を足せる（シナリオにも保存）
- スマホの行動画面（ストーリー時）: 公開された選択肢 ＋ 一般的な行動（調べる・話す・交渉・脅す・隠れる）＋ 自由記述。**一般的な行動と自由記述には技能を決め打ちしない**（GM が判定ボードで技能を選ぶ）
- **判定ボード**: 1 行 = 「誰が・何を・能力値 + 技能・難易度・出目・合計・結果」。プレイヤーが選ぶと自動で行ができる。GM も行を足せる
  - 難易度は GM が決める。目安のボタンは 3b・5a と同じ「難易度目安（DV値）」
  - 計算式と成功ラインを、行とスマホの両方に出す（SPEC §5.0.1。重傷・瀕死のペナルティも入れる）。`packages/rules` の `resolveCheck` / `neededRoll` / `formatNeeded` を使う
  - 出目: スマホから届く、または GM が入れる。10 と 1 の追加の出目を求める（4a §11.6 と同じ）
  - **対抗判定**（相手も振る。`resolveOpposed`。同値は受動側の勝ち）、**全員で同じ判定**（グループ。参加者を選んで同じ技能・難易度の行をまとめて作る）
- **結果の反映**: 行の結果に応じて、選択肢の `on_success` / `on_failure` を「反映する内容」に一覧で出し、GM の「確定して反映」で反映する（4a と同じ流れ。取り消せる）
  - 次のシーン → 進行モードのシーンを移す
  - 手がかり・ハンドアウトの公開 → `revealed` に足し、スマホに届ける
  - HP の増減・状態の付与 → `characters` に書き、4a と同じく重傷・瀕死を自動で付け外しする
  - アイテムの入手 → 所持品に入れる（Phase 3a の形）
  - メモ → セッションログに残す
- スマホには、自分の行の結果と、自分に関係する変化だけを送る（他人の数値は送らない）

## 4. 手がかり・ハンドアウトの公開

- 「公開」でプレイヤーのスマホの新しいタブ「資料」に届く（タイトル・本文・画像）。「非公開に戻す」でスマホから消える
- 画像が `visibility = gm` なら公開できない（警告を出す）
- TV には、GM が「TV にも出す」を選んだものだけ出す

## 5. セッションログ（SPEC §5.3「進行モード」）

- `session_log`（id, scenario_session_id, at, kind（note / scene / check / combat / transaction / money / reveal）, text, ref(JSON)）
- GM の時刻つきメモ、シーンの移動、判定の結果、戦闘の開始と終了（4a の `combat_log` へのリンク）、取引（3a）、資金の送付（Phase 2）、公開を自動で記録する
- 進行モードの下にログを時刻順で出す。「書き出し」（テキスト）
- 成長ポイント（IP）の配布は作らない（Issue #17）

## 6. エンカウンターの戦闘投入

- 5a の `encounters` に「戦闘に入れる」ボタン。4a の参加者チェックを、エンカウンターの参加者（NPC・モブと人数・陣営）と、そのシーンにいる PC で埋めて開く。モブの人数分は 4a と同じく複製する
- エンカウンターに位置があり、シーンに盤面があれば、その位置にコマを置く
- 戦闘が終わったら進行モードに戻る（ログに結果を残す）

## 7. データ・API・保存

- マイグレーション: `scenario_sessions`、`session_log`、`boards.fog`、`scenes.is_adhoc`、判定ボードの行 `story_checks`（id, scenario_session_id, scene_id, choice_id null, actor_character_id, skill_key null, dv null, opposed(JSON) null, rolls(JSON), result, applied_log_id null）
- API（GM だけ。入出力は zod）: 進行の開始・終了・シーン移動、選択肢の公開、判定ボードの行の作成・更新・`resolve`・`apply`・`undo`、公開・非公開、ログ
- WebSocket: プレイヤーから `story:choose`（選択肢・一般的な行動・自由記述）、`story:roll`（出目。自分の行だけ。ほかは 403）。プレイヤーへ `story:choices`、`story:result`、`handout:update`、`display:update`
- 保存ファイル（cpgm-save）の `version` を 6 に上げ、上の表を含める。1〜5 も読めるようにする

## 8. テスト

- 単体・結合
  - 進行: 開始 → シーン移動（分岐・ほかのシーン）→ 臨時シーン → 終了。ログに残る
  - 視界: 隠したマスのコマとオブジェクトが `screen:update` に入らない。GM には入る
  - 判定: 普通の判定・10 の追加・1 の追加・対抗（同値は受動側）・グループ。重傷のペナルティが式に入る
  - 反映: 成功で手がかり公開 + 次のシーン、失敗で HP −3 と状態、取り消しで全部戻る
  - 権限: player は他人の行の `story:roll` ができない、他人の結果を受け取らない、非公開の手がかりを取れない
  - 公開: `visibility = gm` の画像のハンドアウトは公開できない
  - エンカウンター: モブ 3 体のエンカウンターから戦闘 → 参加者チェックにモブ #1〜#3 と PC
  - 保存: version 6 の保存と読み込み、1〜5 の読み込み
  - §0: playwright の `IMAGES_DIR` が `data/` の外
- E2E: 5a のテンプレートで進行開始 → 選択肢「裏口を探す（知覚）」を公開 → ヴァイパーのスマホで選んで出目を送る → GM が難易度を決めて確定 → 手がかりがスマホの「資料」に届き、次のシーンに移る → エンカウンターから戦闘 → 戦闘終了で進行に戻る
- スクリーンショット: 進行モード（1440px）、判定ボード（1440px）、視界を隠した TV（1920px）、スマホの行動画面（ストーリー時）と「資料」（390px）

## 9. やらないこと

- 成長ポイント（IP）の配布（Issue #17）
- AI による文章や画像の生成
- プレイヤーのスマホへの盤面の表示（SPEC §5.0。背景画像は出してよい）
- ネットラン、車両戦闘
- ログイン・パスワード・PIN など、指示書にない仕組み
