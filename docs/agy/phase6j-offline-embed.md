# Phase 6j: PWA オフラインカタログと Google サイト用キャラ作成書き出し

- 対象 Issue: #37（PWA / Google サイト版キャラ作成）、関連 #19（Google サイト埋め込みの要検証）
- 実装ブランチ: `agy/phase6j-offline-embed`
- ベース: `main`
- 作業環境: Windows Orca runtime `G-windows` の CyberPGM worktree
- 実装担当: AGY。指示書作成と監査: Codex

## 目的

`docs/SPEC.md` §9、§10 Phase 6、§12.2、§12.3、§12.4 に沿って、次の2点を実装する。

1. CyberPGM を PWA としてインストールできるようにし、事前に取得した品目カタログをオフライン時に閲覧できるようにする。
2. GM が設定した作成方法・開始資金・購入可能な品目範囲・GM メールアドレスを反映した、Google サイトへ貼り付けられる単一 HTML ファイルを CyberPGM から書き出す。

既存の承認済みデザインシステムとキャラ作成画面を再利用し、新しい画面表現を独自に起こさない。

## 作業場所とブランチ

1. `G-windows` 上の登録済みリポジトリ `C:/Users/sugr3/CyberPGM` から Orca 管理 worktree を作成する。対象 issue は #37。
2. ブランチは `agy/phase6j-offline-embed`、base は最新 `main`。
3. 既存の `agy/phase6i-db-io` worktree は再利用・変更しない。
4. AGY の起動前に `%LOCALAPPDATA%\agy\bin\agy.exe models` を実行し、利用可能なモデルを確認する。リポジトリ運用ルールに従い、一覧にある `gemini-4-argon-high` を使う。利用上限等で起動できない場合は、確認できた別の `gemini-*-flash-high` を使い、その理由を報告に記す。Claude モデルは使わない。

## 実装範囲

### A. PWA とオフラインカタログ

- Web アプリに適切な Web App Manifest、インストール用アイコン、Service Worker を追加する。
- オンライン時にカタログのオフライン閲覧用スナップショットを保存し、オフライン時に品目の名前・種別・価格・閲覧に必要な性能情報を検索・表示できるようにする。
- オフライン閲覧用画面には通信状態と「閲覧のみ」を明示する。オフライン中のキャラクター送信・GM 操作・DB 更新をキューに積んだり、成功したように表示したりしない。
- キャラクター、プレイヤー、セッション、シナリオ、セーブデータ、キャラ受付、ユーザーが選んだ画像、DB ダンプを Service Worker / IndexedDB の永続キャッシュに保存しない。API 全体をキャッシュしない。保存対象は品目カタログに必要なテキスト・数値フィールドに限定する。
- 古いスナップショットの更新・破棄・スキーマ更新を安全に行う。キャッシュ保存に失敗してもオンライン画面を壊さない。
- 新しい npm パッケージを追加する場合は、既存 Vite 構成だけでは不十分な理由とパッケージ名を報告する。

### B. Google サイト用キャラ作成ページの書き出し

- GM 画面から設定を確認・指定して、自己完結した HTML 1 ファイルを書き出せるようにする。既存 UI とデザインシステムを使う。
- ファイル内に含めるのは以下だけ:
  - GM のメールアドレス
  - 作成方法・開始資金
  - GM が選んだ購入可能範囲の品目カタログ（名前・価格・性能の文字データ）
  - 共有する必要がある場合の技能説明など、SPEC §12.4 が定める文字情報
- 画像・アイコン・スキャン・他のプレイヤーの情報・GM の保存データは含めない。生成した HTML は外部サーバー、CDN、CyberPGM API へ通信しない。
- キャラ作成は既存 `CharacterCreatePage` の手順・検証・デザインを可能な限り再利用する。PC/スマホ双方で 360px から操作できる。
- 作成途中のデータは埋め込みページを開いたブラウザ内だけに保存する。既存のルール検証を使い、能力値・技能・開始資金等を確認できるようにする。
- 「GM に送る」では、画像を含む JSON データをユーザー操作でファイル保存し、GM 宛メール作成を案内する。ブラウザの mailto で添付できると仮定しない。対応する場合は Web Share API のファイル共有を機能検査し、使えない場合はファイル保存・コピー可能なテキストコードへフォールバックする。
- テキストコードは文字数上限・破損検出・復元を実装してテストする。長さやデータ量の制限を黙って切り詰めない。
- 生成 HTML を一時ディレクトリで試験し、バンドルが実際に単一ファイル内で完結すること、ネットワーク通信しないこと、禁止データを含まないことを検証する。テスト用に生成した HTML（テスト用メールアドレスやテストカタログを含む）はリポジトリへコミットしない。

### C. Google サイトの実環境検証の境界

- #19 にある Google サイトのアカウント設定・閲覧者限定・実サイト公開は行わない。外部サービスへの公開やユーザーの Google アカウントへのアクセスが必要だからである。
- 代わりにローカルの sandbox iframe 試験ページで、埋め込み設定時のダウンロード・Web Share・メールリンク・画像選択の動作と制限を試す。利用可能な実ブラウザで確認し、試験したブラウザ・OS・制約を報告する。
- 実環境でしか確かめられない項目（Google Sites の実サイズ上限、閲覧者限定、iOS Safari / Android Chrome の実機差）は未検証として #19 に具体的に記録し、推測で完了扱いにしない。
- 公開 URL の作成、サイトへのアップロード、外部共有、ポート公開はしない。

## 禁止事項

- `main` に実装コードを直接書かない。AGY が push してよいのは `agy/phase6j-offline-embed` だけ。
- `data/` の既存 DB、ルール資料、FVTT checkout、ユーザーのブラウザデータ・Cookie・アカウントには触れない。
- 本文・スキャン画像・私有データ・個人パスをコミットしない。
- 本番サーバー、ポート 8787、system 設定を変更しない。
- 指示外の機能、追加サプリ、未確定ルールを実装しない。

## テストと成果物

- `npm run lint`
- `npm run typecheck`
- `npm test`
- PWA: Service Worker / manifest / offline snapshot / no-private-cache のテスト。
- Embed: 単一 HTML 化、データ範囲、オフライン性、文字コード復元、サイズ制限、iframe sandbox のローカル試験。
- E2E は専用ポート 8791 で実行する。ユーザー用サーバーのポート 8787 は使わない。
- GM の書き出し操作とキャラ作成の画面を PC 幅 1440px・スマホ幅 390px で撮影し、報告に添付する。スクリーンショットに個人情報・実データを含めない。
- 報告 `docs/agy/reports/phase6j-offline-embed-01.md` を作り、モデル・変更点・コマンドと終了コード・テスト件数・撮影画像・試験したブラウザ・未検証事項・#19 の状況を記録する。
- lint/typecheck/test の結果を実際の出力から記録する。前フェーズ同様の既知失敗があれば失敗名と原因を記載し、成功扱いしない。
- 作業完了後は変更を目的別コミットで `agy/phase6j-offline-embed` に push し、main には触れずに報告する。
