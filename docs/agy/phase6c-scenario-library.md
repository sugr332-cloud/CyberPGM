## 1. ゴールと範囲

空DBで通常起動すると「ネオンの帳簿」が一覧に現れ、作品を選択して開始すると導入が表示される。GMはJSON取り込み、メーカー編集、NPCの手動関連付けをせずに進行できる。参加キャラの選択と実ダイス出目の入力は通常のプレイ操作として残す。

対象は10シーン・15選択肢・3結末のオリジナル作品1本。外部11作品は参照カタログとして配布元リンクだけを表示する。本文の自動取得・翻案、AI裁定、IP自動配布は対象外。

## 2. 確認済みの起点と不足

- PR #39は素材JSONとREADMEを追加するが自動登録はない。
- 全15選択肢のskill_keyとdvが空。即時の意思決定と設定不足の判定を区別できない。
- 既存applyは判定結果を要求する。判定不要の選択を確定する経路が必要。
- npc_idsと遭遇participantsが空。start-combatは空配列でも戦闘を作成し、不明なcharacter_idを読み飛ばす。
- JSON importのinsertScenarioCopyはIDを再発行する。NPC参照も含む配布単位の解決と、作品キー・版番号による重複防止が必要。
- startは既存セッションを終了してから導入シーンを決定する。事前検証失敗で既存進行を失わないようにする。
- 既存scenario-playの単体・E2E試験は活用する。同梱作品自体の登録から完走までの試験を追加し、既存試験がないとは報告しない。

## 4. 小フェーズ別の要求と確認

### 6c-1: パッケージと検証

- 安定した作品キー、版番号、開始シーンID、シナリオ、NPCテンプレート、必要な装備参照を持つ配布形式を設計する。通常のScenarioFull importとの互換方針を示す。
- 全IDの一意性、シーン所属、遷移先、手がかり、ハンドアウト、NPC、装備、遭遇、条件式、開始シーンを検証する。終端シーンと到達不能シーンも確認する。
- 選択肢方式はinstant/check/gm相当の明示フィールドで区別。checkの技能・難易度または対抗相手の欠落を検出する。
- 旧データのnullをinstantに自動変換しない。既存の自由行動・後からGMが設定する判定を壊さない。
- 確認: 不正な参照・重複ID・開始シーン欠落・不完全判定を拒否し、DBに部分登録が残らない。

### 6c-2: 同梱登録と版管理

- 通常起動時、DBマイグレーション後に同梱作品を登録。作品キー＋版番号を一意にし、登録全体をトランザクションにする。通常のデモseedに依存させない。
- シーン・選択肢・公開資料・NPC・遭遇の参照を一括変換する。ローカルの既存IDを配布JSONに固定しない。
- 再起動・同時登録で重複しない。更新版は別版として保持し、進行中・中断中の版を固定する。ユーザー編集は複製作品として保持する。
- 確認: 空DB、既存DB、再起動、再登録、途中失敗、旧版での再開、新版での新規開始を試験。配布成果物にパッケージが含まれ、ネットなしで読める。

### 6c-3: 判定不要の選択肢

- instantは選択→効果のプレビュー→GM確定で実行。プレイヤーのタップだけではシーンを進めない。gm方式は裁定結果・理由を記録できる。
- checkと効果適用処理を共通化し、シーン移動・公開・状態・履歴・取消を扱う。
- セッション、現在シーン、選択肢の所属、権限を検証。二重送信を識別し二重反映しない。古いシーンの要求を拒否する。
- 確認: 依頼受諾、撤退、3結末をダイスなしで実行。再送・取消・別セッションからの要求を試験。

### 6c-4: 判定と条件の完成

- 交渉・解錠等の技能キーと難易度を明示。独自シナリオの設計値はその旨を記録し、公式ルール定数と混同しない。
- 成功・失敗それぞれの遷移と、手がかり・ハンドアウト公開の契機を定義する。表示用リンクは実行定義から生成するか、整合性検証を必須にする。
- 警戒、交渉成立、救出等をセッション固有状態にする。保存・再開・取消に含める。
- グループ判定の代表者・全員成功・一人成功等の集約方法をシナリオ側に明示し、シーン遷移を一度だけ確定する。
- 確認: 交渉成功→搬入口／失敗→倉庫、解錠成功→救出／失敗→倉庫、倉庫交渉失敗の再挑戦、撤退ループを試験。10・1の追加出目、難易度同値失敗、二重適用、取消も既存ルール試験と照合する。

### 6c-5: NPCと遭遇

- ミカ、レン、カイ、ヴェイル、警備員を登場シーンへ関連付ける。会話用NPCと戦闘用NPCを区別する。
- ヴェイル＋警備員2名の能力値・技能・HP・装備参照を完成させる。公式テンプレート利用時は出典・利用条件を照合し、既存SPEC §3に従って配布可否を判断する。転載不可データをcommitしない。未確認値を埋めて完成扱いしない。
- 配布できる独自NPC設計、またはローカル資料への依存を明示する。必要データが不足している間は「準備不足」と表示する。最終受入時には新規環境で必須の手動紐付けを残さない。
- 戦闘生成前に敵数、全NPC・装備参照、現在シーンとの所属、既存戦闘を検証。参照切れを黙って読み飛ばさない。生成・参加者・コマ作成を原子的に扱う。
- 確認: 敵3名、警備員の個別HP、参加PCのみの有効化、空遭遇・不明参照・二重開始の拒否。盤面がある場合は範囲内配置と重複コマ防止も確認。

### 6c-6: 戦闘からの復帰

- セッション・遭遇・戦闘の関連を保持。勝利・交渉成立・撤退をGMが確定し、対応する次シーンと状態を適用する。全滅だけで勝利を自動裁定しない。
- 「敵を制圧したとして救出」は解決済み条件または理由付きGM裁定を要求する。
- 確認: 戦闘勝利→救出、交渉→救出、撤退→搬入口。進行再開後の二重戦闘生成・二重救出を防止。

### 6c-7: 一覧から開始

- 「プレイ可能」「準備不足」「外部参照」を区別。概要・人数・所要時間を出し、準備不足は不足項目を具体的に示す。
- 開始APIで登録・参照・開始シーン・使用版・必要データを再検証。検証後に既存進行の中断と新規開始を一つのトランザクションで実施する。
- 進行中セッションがある場合は中断・再開の既存導線を尊重し、黙って失わせない。サーバーの二重開始防止とUIの送信中制御を行う。
- 報酬の標準案と3結末の終了案内を用意。報酬変更は任意、IPは案内だけ。クリアは既存処理でキャラの拘束を解除する。
- 確認: JSON取り込みゼロで導入表示。開始失敗で既存進行が保持される。外部11作品には配布元リンクのみを表示する。
- UI変更は既存モック・デザイントークンを使用し、必要な追加モックをClaudeが審査する。

### 6c-8: 統合検証

- 同梱作品を実際に読み込み、テスト用に手組みした別シナリオだけで代替しない。
- 3結末へ到達する経路、戦闘経路、交渉失敗、解錠失敗、撤退と再進入、手がかり公開を網羅する。
- PCのGM画面＋スマホで選択・実ダイス入力・GM反映・資料閲覧を確認。GMメモ、敵の秘密情報、未公開資料をプレイヤー向けAPI/WSに含めない。
- 判定反映後・戦闘中・結末直前の保存と読み込み、中断再開、クリア後のキャラ解放を試験。新しい状態・関連を保存形式へ含め、旧保存の互換性を維持する。
- lint、typecheck、単体・結合、同梱作品E2E、関連する既存E2Eを実行。失敗と未実行を区別して報告する。
- テスト用DB・画像は一時領域を使用。本番data/および稼働中8787には触れず、E2Eは既存設定の8788を使う。
- PC 1440px、スマホ390pxの一覧・導入・判定・資料・結末のスクリーンショットを報告。実機確認が終わるまでフェーズ全体を完了にしない。
