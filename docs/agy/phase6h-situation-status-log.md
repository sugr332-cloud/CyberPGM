## A. 状況修正（Issue #31）

日本語版 p.130「判定修正値」の不利な修正の例（GM が課す修正は累積する）:

| key | 状況 | 修正値 |
|---|---|---|
| dim | 夜または薄暗い状況 | −1 |
| untrained | まったく未経験の行為をする | −1 |
| complex | 複雑な行為 | −2 |
| lacking_tools | 道具や部品が不足している | −2 |
| no_sleep | 前夜の睡眠が不足している | −2 |
| stress | 極端なストレスにさらされている | −2 |
| exhausted | 極度に疲労している | −4 |
| intoxicated | 酒や鎮静剤を過剰に摂取している | −4 |
| covert | 行為を秘密裏に行なう | −4 |
| obscured | 煙や暗闇で視界が悪い | −4 |

- この表を `packages/shared` に定数で置く（ページ番号 p.130 をコメントに書く）
- GM の戦闘画面で、判定ごとに状況を**複数チェック**できるようにする。加えて、表にない状況のための「その他 ±」の数値欄を 1 つ付ける（GM が自由に入れる。既定 0）
  - 戦闘全体にかかる状況（暗闇・煙など）を毎回選び直さずに済むよう、**戦闘ごとの既定**として保持し、判定欄の初期値にする。判定ごとに外したり足したりできる
- 選んだ修正は、Phase 6f で作った**共通の修正値リスト**（`apps/server/src/services/attack-modifiers.ts`）に入れ、成功ラインの案内と実際の判定の両方に同じ値で効かせる。内訳には「煙や暗闇で視界が悪い −4」のように 1 つずつ出す
- 攻撃・回避以外の技能判定（応急手当など、戦闘画面から行うもの）にも同じ欄を効かせる
- スマホ側は、GM が選んだ修正が内訳に出るだけでよい（スマホから選ばせない）

## B. 状態異常の付け外し（Issue #34）

今の作り: 状態は `character.status`（文字列の配列）、残りラウンドは参加者の `state.statusRounds`。ラウンドが進むと減る処理はある。重傷・瀕死・死亡は HP から自動で付く。気絶・伏せ・つかみは行動の結果で付く。

- GM の戦闘画面の参加者カードに、状態を**手で付ける・外す**操作を付ける
  - 付けられる状態は、**今アプリが判定に使っている状態名だけ**（`combat-resolver.ts` などで実際に効果があるもの。例: 気絶・伏せ。炎上など環境の状態が既にあればそれも）。一覧はコードから拾って報告に書く。効果のない新しい状態名は作らない
  - 付けるときに残りラウンドを入れられる（空欄 = 解除するまで続く）。今の `statusRounds` の仕組みを使う
  - HP から自動で付く状態（重傷・瀕死・死亡）は手で外せない（HP を直すと変わる、と表示）
  - つかみは相手との組（`grappling` / `grappled_by`）があるので、手で外すときは両者の組を同時に解く
- 付け外しは戦闘ログに残し、「一手戻る」で戻せること
- 参加者カードとスマホに、状態と残りラウンド（「気絶 あと 3R」）を出す。既にある表示があればそれを使う

## C. 戦闘ログをセッションログへ（Issue #35）

- 戦闘を終えたとき（「戦闘を終える」）、その戦闘がシナリオのセッションに属していれば、取り消されていない `combat_log` を要約してシナリオのセッションログ（`session_log`）に保存する
  - 1 行の形の例:「R2 ジャック → ガンナー ハンドガン 命中 ダメージ 9（SP 7 で 2 通る）」。判定の内訳（成功ライン・出目）も読める形で残す。今の `breakdown` から作る
  - 戦闘の開始・終了、倒れた／気絶した参加者、使った弾も分かるように
  - セッションログに 1 戦闘ぶんのまとまりと分かる区切り（見出し行など）を付ける。`session_log.kind` は既存の値を確認し、新しく使うなら報告に書く
- シナリオに属さない戦闘は何もしない
- シナリオ画面のセッションログで、その内容が読めることを確認する
- 二重に保存しない（戦闘を終える操作を 2 回押した、終了を取り消して再度終えた、など）

## D. テスト

- 単体: 状況修正の合計（複数選択・その他 ±・戦闘ごとの既定）、状態の手動付与と残りラウンドの減少、戦闘ログの要約の文字列
- E2E: 煙を選ぶと成功ラインの内訳に −4 が出て判定にも効く／気絶を手で付けると行動がグレーになり、ラウンド経過で外れる／シナリオから始めた戦闘を終えるとセッションログに戦闘の要約が出る
- `npm run lint`、`npm run typecheck`、`npm test`、関係する既存 E2E（`combat-flow`、`combat`、`board-combat`、`action-guard`、`phase6a`、`phase6f`）を通し、結果を報告に貼る
- スクリーンショット: GM の判定欄（状況修正）、参加者カードの状態付与、セッションログ
