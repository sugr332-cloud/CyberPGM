## A. 戦闘中のコマのドラッグ移動

### 今の動き

- `apps/web/src/components/BoardView.tsx`
  - `handleTokenMouseDown` と `handleObjectMouseDown` は、`combat?.status === 'active'` のとき何もしない
  - そのため戦闘中は、GM がコマをマウスで動かせない
- 戦闘中の移動は、行動「移動」「走る」を選んで、移動できるマスから移動先をクリックし、「移動を確定」を押す（`CombatView.tsx` の `destination` と `reachableCells`）

### 作るもの

- 戦闘中でも、GM 画面ではコマをドラッグして、好きなマスに置けるようにする
  - TV 画面（`isScreen`）とプレイヤー画面は今までどおり動かせない
- 置いたときの扱いは 2 通り:
  1. **手番の人のコマで、行動「移動」か「走る」を選んでいるとき**
     - 落としたマスを移動先（`destination`）にする。クリックで選ぶのと同じ扱い
     - 移動できないマス（`reachableCells` にない）なら、移動先にしない。コマは元の場所に戻し、「そのマスへは移動できません（移動力 ○ マス）」と出す
     - 確定は今までどおり「移動を確定」ボタン。移動力の消費などは既存の処理のまま
  2. **それ以外（GM が位置を直すとき）**
     - そのマスへそのまま置く。移動力は使わない
     - 戦闘ログに「GM がコマを動かした: 名前 (x1,y1)→(x2,y2)」を残す
     - 「一手戻る」で元の位置に戻せるようにする。今ある `CombatChange` の仕組みに、コマの位置を戻す変更を足す。行動の結果ではないので、解決処理（resolver）は通さず、専用の API で記録してよい
- ドラッグ中の見た目:
  - つかんだコマを半透明にする
  - マウスの下のマスを枠で示す。移動中なら、移動できるマスは緑、できないマスは赤
  - 盤面の外で離したら、元の場所に戻す
- 置けないマス:
  - 壁などのふさがったマス、他のコマがいるマスには置けない。既存の判定があればそれを使う
  - 置けないときは元に戻して理由を出す
- オブジェクト（遮蔽物など）のドラッグは、戦闘中は今までどおり動かせなくてよい
- タッチ操作（タブレット）でも動くよう、`onMouseDown` 系ではなく Pointer Events（`onPointerDown` / `onPointerMove` / `onPointerUp`、`setPointerCapture`）で作る
  - 戦闘前の配置も同じ処理に寄せてよい。その場合も今の動きを壊さないこと
- 動かした位置は、今までどおり WebSocket で TV 画面・スマホに反映されること

### テスト

- 単体: コマ位置の変更を記録し、「一手戻る」で戻ること
- E2E（`e2e/` に足す）:
  - 戦闘中に GM がコマをドラッグして、別のマスに置ける
  - 「移動」を選んで、移動できないマスに落とすと元に戻る
  - 「一手戻る」で元の位置に戻る

## B. キャラクター作成で技能の詳細を見られるようにする

### 出すところ

- GM の PC 編集画面（`apps/web/src/components/CharacterEditorView.tsx` の技能一覧）
- プレイヤーのキャラ作成ページ（`apps/web/src/pages/CharacterCreatePage.tsx` の技能を振る画面）
- 技能名の横に「？」ボタンを置き、押すと詳細を開く。もう一度押すと閉じる
  - スマホ幅（390px）でも読めること

### 出す内容

1. **計算方法**（アプリの中のデータから作る。公開してよい）
   - 判定 = 能力値 + 技能レベル + 1d10
   - 結びつく能力値の名前と、今のキャラの値を入れた式。例: 「【反応】6 + 〈ハンドガン〉4 + 1d10」
   - 上げるのに必要な成長ポイントが 2 倍の技能（×2）なら、そのことを書く
   - 基本技能（全員が最初から持っている技能）かどうか
   - 種類を選ぶ技能（武術・演奏・科学・言語・土地鑑）は、種類を選ぶことを書く
2. **効果と使い道**（ルールブックの要約。git 管理外の手元資料から読む）
   - どんな場面で使う技能か、何ができるか
   - 戦闘で使う技能なら、アプリのどの行動で使うか（例: 〈ハンドガン〉→「射撃」、〈回避〉→ 射撃をよける）。行動との対応はアプリのデータ（`docs/data/combat-actions.ja.json` など）から作る
   - 対抗判定になる組み合わせがあれば書く（例: 〈隠密〉と〈知覚〉）
   - 参照ページ（日本語版 p.○）

### 手元の技能資料（git 管理外）

- `data/sources/core-ja/skills.json` を新しく作る。**このファイルは commit しない**
- 元にするのは手元の要約 `data/sources/core-ja/rules/*.md`
  - 技能の一覧と要点: p.81〜85（`INDEX.md` で「技能」の行を探す）
  - 技能の詳しい説明: p.130 以降の技能の章
- 形:

  ```json
  {
    "note": "日本語版コアルールブックの要約（手元用。commit しない）",
    "skills": {
      "handgun": { "summary": "…", "uses": ["…"], "opposed": ["…"], "pages": [82, 135] }
    }
  }
  ```

  - キーは `packages/shared/src/skills.ts` の技能キーにそろえる
  - 種類を選ぶ技能は、基本キー（`martial_arts` など）に書く
- 書き方:
  - 本文を丸写ししない。1 技能につき 1〜3 文の要約と、使い道の箇条書き
  - 資料にない技能は項目を作らない。報告に「資料にない技能」として名前を並べる
- 読み込みは `loadRoleData()`、`loadNetrunData()` と同じ方法で `loadSkillInfoData()` を作り、`GET /api/skill-info` で返す
  - ファイルがないときは、計算方法だけを出す。効果と使い道の欄には「技能の説明（手元のルール資料）がありません」と出す
  - テストでは、`apps/server/test/roles.test.ts` と同じように一時ファイルを作り、終わったら消す
- 公開リポジトリなので、`packages/` や `apps/` のコードに技能の説明文を書き込まない
  - 計算に使う数値（能力値の対応、×2、基本技能かどうか）はコードにあってよい

### テスト

- 単体: `/api/skill-info` がファイルありとなしの両方で正しく返す
- E2E: PC 編集画面とキャラ作成ページで「？」を押すと、式（能力値の名前と値）と説明が出る

## C. 追加の要望（2026-10-22、同じブランチで行う）

> プレイヤーは移動コマンドを押したときにマップで自身を触れる。gm側は、いつでも誰でも触れるようにしてください。行動できないボタンはグレーにして、押すと、その行動ができない理由を付けてエラー文章をだして

### C-1. GM はいつでも誰のコマでも動かせる

- A のとおり。戦闘前・戦闘中・手番でない人・NPC・敵、どのコマでも GM はドラッグできる
- 手番の人で「移動」「走る」を選んでいるときだけ、落としたマスが移動先になる（A の 1）。それ以外はすべて位置の手直し（A の 2）

### C-2. プレイヤーは「移動」を押したとき、スマホのマップで自分のコマを動かせる

- 今のプレイヤー画面（`apps/web/src/pages/PlayerPage.tsx`）にはマップがない。行動タブで「移動」（「走る」があればそれも）を押したら、マップを出す
  - 盤面は `GET /api/boards/:id` の見え方（霧・GM だけのもの）を TV 画面と同じにする。GM だけの物や霧の下はプレイヤーに見せない
  - 390px 幅に収める。拡大縮小・スクロールできるとよい
- 動かせるのは**自分のコマだけ**、**自分の手番で「移動」「走る」を選んだときだけ**。他人のコマはさわれない
- 移動できるマスを緑で示す。できないマスに落としたら元に戻し、理由を出す（例: 「そのマスへは移動できません（移動力 6 マス）」）
- 落としたら、その移動先を GM に送る
  - 今ある WebSocket の `combat:choose` と同じやり方で、行動と移動先を送る。サーバーで「本人のコマか」「手番か」「移動できるマスか」を確かめ、だめなら理由を返す
  - GM の戦闘画面では移動先にそのマスが入り、「プレイヤーが選んだ移動先」と表示する。確定は GM が「移動を確定」で行う（出目を送るときと同じ流れ）
  - 確定前ならプレイヤーは置き直せる
- プレイヤーがコマの位置を直接書き換える API は作らない（`PATCH /boards/:id/tokens/:tokenId` は GM 専用のまま）

### C-3. できない行動のボタンはグレーにし、押したら理由を出す（Issue #30）

- GM の戦闘画面とプレイヤーのスマホ画面の、行動を選ぶボタンすべてが対象
- 今その行動ができないときは、ボタンをグレーにする。ただし**押せるままにして**、押したら理由のエラー文を出す（`disabled` にすると押しても何も起きないので、`aria-disabled="true"` と見た目で表す）
  - GM 画面: 既存のエラー表示の場所に出す。プレイヤー画面: 画面下に数秒出る通知など、既存の出し方に合わせる
  - 文は「何ができないか」と「なぜか」と、できれば「どうすればできるか」。例:
    - 「射撃できません: 弾が 0 発です。リロードしてください」
    - 「移動できません: このターンはもう移動しました」
    - 「NET アクションできません: ジャックインしていません」
    - 「行動できません: 気絶しています」
- 理由はサーバーの判定と同じものを使う。画面とサーバーで別々の条件を書かない
  - 今ある判定（`combat-resolver.ts`、`netrun-resolver.ts` などがエラーで返している条件）を、行動を実行せずに確かめられる関数として共通化し、戦闘の状態を返すときに行動ごとの「使えるか・理由」を付ける。または、それを返す API を作る
  - 共通化しても、実行時のサーバー側の判定は残す
- 対象にする条件は、少なくとも次のとおり（コードにある判定はすべて拾う）:
  - 手番でない / 行動をもう使った / 移動をもう使った
  - 弾がない（射撃・オートファイア・制圧射撃）、オートファイアできない武器、リロードできる弾がない
  - 気絶・死亡・つかまれている・伏せ・乗り物の中など状態による制限
  - ネットラン中の肉体アクションと NET アクションの排他、NET アクションの残り回数
  - 持っていない武器・装備・サイバーウェア・プログラムが要る行動

### テスト（追加）

- 単体: 行動ごとの「使えるか・理由」が、実行したときのサーバーのエラーと同じ文になる（弾 0 の射撃、移動済みの移動、気絶中、ジャックインなしの NET アクション）
- 単体: プレイヤーが送った移動先を、本人以外・手番以外・届かないマスなら断る
- E2E:
  - スマホで「移動」を押すとマップが出て、自分のコマを緑のマスへ置くと GM 画面の移動先に入る。他人のコマは動かない
  - 弾 0 で射撃ボタンがグレーになり、押すと理由が出る（GM 画面とスマホ画面の両方）
- 報告のスクリーンショットに、スマホ（390px）でマップから移動先を選んでいる様子と、グレーのボタンを押して理由が出た様子を足す
