## A. HP バーにダメージが反映されない

HP の数値は「確定して反映」で減る（Phase 6c で確認済み）。バーが減らない場所を見つけて直す。

- HP バーは少なくとも 4 か所にある。すべて確かめる:
  - GM 戦闘画面の参加者カード（`CombatView.tsx` の `hpPercent`）
  - 盤面のコマの下のバー（`BoardView.tsx` の `currentHp`）
  - TV 表示（`ScreenPage.tsx` の `percent`）
  - プレイヤー画面のシート（`PlayerPage.tsx` の `hpPercent`）
- Claude の見立て（確かめてから直すこと）: `BoardView.tsx` はコマ自身の `tok.hp` を、キャラの `char.hp` より優先している。コマの `hp` がダメージで更新されていなければ、バーは古い値のまま。ほかの画面も、ダメージ後に読み直すデータ（キャラ一覧・盤面）が更新されていない可能性がある
- 直し方: 戦闘の参加者・コマの HP は、いつも最新のキャラの HP（戦闘中なら `characters.hp`）から表示する。ダメージ・回復・「一手戻る」のあと、再読み込みなしで 4 か所すべてのバーと数値が変わること
- E2E: `e2e/combat-flow.spec.ts` に、攻撃を確定したあと 4 か所のバーの幅（または `aria-valuenow` など、テストで読める値）が減ること、「一手戻る」で戻ることを足す。直す前に失敗することも確かめ、報告に書く

## B. GM 側の武器選択にもダイスを出す

Phase 6c までで、プレイヤーのスマホの武器選択には「2d6」などのダメージが出ている。GM の戦闘画面にも同じものを出す。

- GM 戦闘画面で、手番のキャラの武器を選ぶところ（武器の選択肢・ボタン）に、**その武器のダメージ（例: `2d6`、`3d6`）** を武器名と並べて出す
  - 値は、そのキャラが実際に持っている武器のデータ（所持品・品目）から取る。プレイヤー側と同じ関数・同じ値を使う
  - 格闘・素手（ブロウル）はルールどおりの値（BODY で決まる）を出す。武術も同様
  - ダメージが分からない武器は「ダメージ不明」と出す（推測で埋めない）
- 武器を選んだあと、ダメージの出目を入れる欄の近くにも「ダメージ: 2d6（6 面ダイスを 2 個）」のように出す（GM がプレイヤーに「6 面を 2 個振って」と案内できるように）
- 単体テスト（ダメージ式の取得）と E2E（GM 画面で 2d6 が見える）を足す

## C. 商店の品揃えをドラッグ＆ドロップで作る

今は、商店を選ぶと在庫に入っている品だけが一覧に出る（`ShopView.tsx` の「If a shop is selected, only show items in shop stock」）。新しい商店は在庫が空なので、何も出ず、品を足す場所がない。在庫の API（`POST /api/shops/:id/stock`、`DELETE /api/shops/:id/stock/:item_id`）はすでにある。

GM の商店画面に「品揃えを編集」を作る:

- 商店を選んで「品揃えを編集」を押すと、2 列の編集画面になる
  - 左: 全品目のカタログ（検索欄、分類〈武器・防具・弾薬・サイバーウェア・車両・装備・服・ドラッグ・プログラム・サイバーデッキ・改造〉の絞り込み、画像・名前・価格）
  - 右: その商店の品揃え（今の在庫。名前・価格・在庫数）
- 左の品を右へ**ドラッグ＆ドロップ**すると品揃えに入る（在庫数は無制限で入る）。複数選んでまとめてドラッグできると良いが、必須ではない
- 右の品を左へドラッグするか「×」で品揃えから外す
- 右の在庫数はその場で変えられる（無制限／数）
- スマホ幅（390px）や、ドラッグがしにくいときのために、各品に「＋ 追加」ボタンも付ける
- すでに品揃えにある品は、左の一覧で分かるようにする（印を付ける。二重には入らない）
- 新しい商店を作ったら、そのまま「品揃えを編集」を開く
- 変更はすぐ保存し、プレイヤーの商店画面にも再読み込みなしで反映されること（既存の通知を使う）
- ドラッグには HTML5 の Drag and Drop を使う。新しい npm パッケージは足さない（どうしても必要なら報告に名前と理由を書く）
- E2E: 新しい商店を作る → 品を 3 つドラッグで入れる → 1 つを外す → 在庫数を変える → プレイヤー画面のその商店に 2 品が出る
