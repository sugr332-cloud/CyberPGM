## ゴール

1. プレイヤーが自宅 Wi-Fi で QR から開き、スマホでキャラを作って GM に送れる（SPEC §12.1・§12.4）
2. GM がキャラ受付で、届いたキャラを確認して取り込める（ファイルからの取り込みも）
3. GM 画面の **技能タブ** で、技能の一覧・計算方法を見て、技能と難易度を選ぶと PC ごとの成功率が出る（SPEC §5.6）

Google サイト版（外からの作成とメール送信）は Phase 6。ここでは作らない。

## 1. 作成方法と数値（ルールどおり。値はまだ確認中）

ユーザー決定: **ポイント数・レベルの上限はルールどおり**。ただし日本語版の値はまだ確認できていない（Issue #7）。**数値を推測で入れない**。

- rule_constants `creation_method.<key>` に、作成方法ごとの値を持たせる: `{ label, stat_points, stat_min, stat_max, skill_points, skill_level_max, basic_skill_min, difficult_cost, uses_starting_funds }`
- 初期データは **値をすべて null** にして、label だけ仮で入れる（例: `complete_package`「完全版の作成方法（仮）」）。GM が設定画面で値を入れる（日本語版で確認したら入れる）
- 値が null の項目は、キャラ作成で **チェックしない**。画面には「未設定のためチェックしません（GM が設定）」と出す
- `difficult_cost` が null のときは、FVTT の `multiplier`（×2 技能は 2）を使ってポイントを数える（FVTT で確認済み）
- 開始資金は `app_settings.starting_funds`（Phase 2。空欄なら資金のチェックをしない）
- GM はキャラ受付の「招待」の欄で、使う作成方法を 1 つ選ぶ。プレイヤーの作成画面はそれに従う

## 2. キャラ作成（プレイヤーのスマホ。モック「プレイヤーのスマホ — キャラ作成」）

入口: QR から開いた参加画面（Phase 2）に「新しくキャラを作る」を足す。`/player/create`。作成途中のデータは localStorage に保存し、閉じても続きから再開できる。

1. **基本**: 画像（撮影または選択 → 四角く切り抜き。Phase 3a の画像アップロードと同じ制限。`origin = 'user'`、`visibility = 'players'`）、ハンドル、ロール（FVTT の roles 10 種。日本語名は babele の `core_roles` から、なければ英語名）
2. **能力値**: 10 個を − / ＋ で決める。残りポイント・上限・下限は §1 の値で検証。「人間性 = EMP × 10」を表示
3. **技能**: モックどおり
   - 区分で絞り込み（区分の表示名: 認識 / 身体 / 操縦 / 教育 / 戦闘 / 演技 / 射撃 / 社会 / 技術。FVTT の category に対応。仮訳）
   - 各技能に − / ＋、`能力値 + レベル = 基本値`、「基本」「×2」のしるし
   - 残りポイントを上に固定表示。上限・最低レベル・コストは §1 で検証
   - 一覧の上に「技能判定の計算方法」を開閉式で出す（基本値 = 能力値 + レベル、基本値 + 1d10 が難易度を超えれば成功、出目 10 / 1 の追加ロール、相手がいるときの対抗、負傷の修正）
   - 技能名をタップすると開く: **使う場面**（§4 の文）、**式**（例: `DEX 6 + 回避 6 = 12 + 1d10`）、**成功の目安**（「日常的（難易度 13）なら出目 2 以上で成功（90%）」。`packages/rules` の `neededRoll` / `formatNeeded` / `successProbability` を使う。13 は Issue #3 の仮の値）、基本 / ×2 の説明、出典（英語版 p. / 日本語版 p.[ ]）
4. **装備**: 商店のカタログ（Phase 3a）を、画像つき・文字で選ぶ。カテゴリで絞り込み。開始資金があれば残りを上に固定表示し、超えたら警告（空欄なら使った額だけ出す）。サイバーウェアには `人間性 −固定値` を出し、選ぶと人間性と EMP がその場で変わる（作成時は固定値。`packages/rules` の `maxHumanity` / `currentEmp`。Issue #8）
5. **送信**: チェック（能力値・技能ポイント・資金。null の項目は「チェックしない」）を出して「GM に送る」。送ったらキャラ受付に入る

## 3. キャラ受付（GM。モック「GM — キャラ受付」）

- 招待の欄: 作成方法を選ぶ、開始資金（Phase 2 の設定と同じ値）、「自宅 Wi-Fi 用の QR を表示」（Phase 2 の参加用 QR）。「Google サイト用の埋め込みコード」は Phase 6 なので、ボタンは置かない
- 届いたキャラの一覧: 画像、名前、ロール、届いた日時、届き方（Wi-Fi / ファイル）、チェックの結果（OK / 資金オーバーなど）
  - 「取り込む」→ PC になる（`characters` の `kind = 'pc'`。所持品と資金と人間性を作成時の内容で入れる。money_log に「開始資金」として記録）
  - 「中身を見る」→ キャラシートと同じ表示
  - 「差し戻す」→ プレイヤーのスマホの作成画面に GM のコメントつきで戻る（Wi-Fi で作ったものだけ）
- **ファイルから取り込む**: `.cpgm` ファイル（キャラデータの JSON: `{ format: 'cpgm-character', version: 1, character, created_with: { method, starting_funds } }`）を選ぶかドロップ → zod で検証 → 一覧に入る。Phase 6 の Google サイト版はこの形式でメールに添付する。プレイヤーの作成画面にも「ファイルに保存」を置き、同じ形式で書き出せるようにする
- 受付中のキャラは `characters` の `kind = 'pending'` か、別テーブル `character_submissions` のどちらでもよい（報告に理由を書く）。保存ファイル（cpgm-save）に含める

## 4. 技能の「使う場面」のデータ

- 初版は `docs/data/skill-notes.ja.json`（Claude が自分の言葉で書いた仮の文。ルールブックの文章ではない。Issue #20）
- これを DB の `skill_notes`（key, text, updated_at）に初回だけ入れる（既にあれば上書きしない）。GM が技能タブで編集できる
- 作成画面と技能タブは、同じ `skill_notes` を使う

## 5. 技能タブ（GM。モック「GM — 技能一覧と成功率」）

- 左: 技能一覧の表。列: 技能（「基本」「×2」のしるし）、能力値、区分、何に使うか（`skill_notes`。その場で編集できる）、出典（英語版 p. / 日本語版 p.[ ]）。区分で絞り込み、名前で検索
- 一覧の下に注記: 「基本 = 全キャラが最低レベルから持つ技能（要確認）。×2 = 上げるコストが 2 倍。技能名・能力値・区分・出典は FVTT のデータ。何に使うかは GM のメモ（ルールブックの文章は写さない）」
- 右: 選んだ技能の計算方法（`能力値 + 技能 + 1d10 − 負傷 vs 難易度`、難易度を超えれば成功（同値は失敗・要確認）、出目 10 / 1 の追加ロール）
- **難易度目安（DV値）** のボタン（日常的 13 / 困難 15 / 専門的 17 / 英雄的 21 / 非現実的 24。日本語版イージー・モード p.15 の訳語と値。9 と 29 に当たる段階はコアルールで確認するまで出さない（Issue #3）。数値の直接入力もできる）
- 「各キャラの成功率を見る」→ PC ごとに: 名前（重傷・瀕死なら印）、式（`INT 6 + 知覚 5 − 2 = 9 vs 難易度 15`）、必要な出目、成功率（%）とバー（70% 以上は緑、40% 以上は黄、それ未満は赤）。負傷ペナルティは PC の今の HP から `woundState` で入れる。技能がない PC はレベル 0
- 成功率と必要な出目の計算は、必ず `packages/rules` を使う（画面で独自に計算しない）
- モックの「この判定を判定ボードに追加」は Phase 5（ストーリーの判定ボード）なので、今は置かない

## 6. テスト

- 作成方法の値が null のときはチェックしない、値があるときは超過を検出する（能力値・技能・×2 のコスト・上限・最低レベル）
- サイバーウェアを選ぶと人間性と EMP が `packages/rules` どおりに変わる
- 送信 → 受付 → 取り込みで PC になり、資金・所持品・人間性・money_log が正しい
- `.cpgm` の書き出しと取り込み、壊れたファイルの拒否
- 成功率: 技能タブの値が `packages/rules` の `successProbability` と一致する（例: 知覚 11 vs 難易度 13 → 80%）。重傷の PC は −2 が入る
- E2E: スマホ幅でキャラを作って送る → GM がキャラ受付で取り込む → PC 管理に出る。技能タブで知覚・難易度 15 を選んで成功率が出る
- スクリーンショット: キャラ作成の 5 画面（390px）、キャラ受付と技能タブ（1440px）
